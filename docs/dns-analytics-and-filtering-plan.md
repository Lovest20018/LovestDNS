# LovestDNS 解析可视化与 DNS 去广告实施方案

A、B、C 已在集成版开发代码中实现。D 为后续增强。使用入口、实际测试和部署覆盖见[使用说明](dns-filtering.md)与[验收记录](dns-analytics-and-filtering-verification.md)。

## 交付目标

用户从首页发现某段时间查询量上升，点图查看当时的查询，再点来源 IP 缩小范围。打开一条记录，可以看到请求和应答；如果由本机过滤器拦截，还可以看到是哪份订阅的哪条规则生效，并临时放行该域名重新测试。AdGuard Home 提供界面组织和 DNS 规则语义的参考，运行时使用 LovestDNS 自己的解析链。去广告作用于独立广告和追踪域名，同域内容中的广告超出 DNS 的识别范围。

建议依次交付 A「解析概览与查询日志」、B「规则订阅与实际过滤」、C「命中详情与放行」。A 可独立验收，B、C 合起来交付完整去广告体验。D「逐请求分流路径」是后续增强。

## A · 从概览进入一次真实查询

| 页面 | 界面与交互 | 数据口径 |
| --- | --- | --- |
| 解析概览 | 参考 AdGuard Home 的概览卡、时间趋势和排行布局，沿用 LovestDNS 现有颜色、字体及窄屏卡片。首行显示已记录查询数、活跃来源 IP 数、P95 响应耗时。下方并排显示热门域名和来源 IP 前十。 | 每条已保留的入口事务计一次，UDP 与后续 TCP 分开；P95 只取有应答且耗时有效的样本，显示样本数。沿用独立的递归、转发 QPS 与缓存趋势。 |
| 查询日志 | 复用「最近查询」。时间段支持最近 1 小时、24 小时和点击图表选中的时间桶。点排行项时保留时间范围和其他筛选；支持返回、刷新和翻页。 | 时间边界统一用 UTC 时间戳和左闭右开区间，页面按本地时间展示。域名排行下钻用精确匹配，文本搜索保留现有的包含匹配。 |
| 解析详情 | 展开一行显示来源、入口、域名、类型、传输、响应码、已观测地址和耗时，保留「重新查询」。在 C 接入过滤判定，在 D 接入实际分流。 | 历史应答和新发起的诊断各自带时间。自然 NXDOMAIN、SERVFAIL、未观察到响应分别展示。来源按入口可见 IP 展示，路由器代转时排行可能只出现一个来源。 |

**后端与存储。** 从 `integrated/runtime/query_store.py`、`query_recorder.py` 和 `integrated/backend/api_v1.py` 扩展现有记录服务。建议新增管理权限的 `GET /api/v1/query-records/summary`，返回窗口、分桶、排行、耗时样本数和采集覆盖状态。给已有列表接口增加时间、域名精确匹配和响应状态等可选筛选。统计覆盖窗口内保存的全部匹配记录，避免用已加载的一页计算。分页沿用游标；下钻时携带同一窗口和快照上界，记录已过期或被清理时提示用户。

**记录边界。** 沿用默认关闭、最长 24 小时、最多 10 万条、数据库 31 MiB 和含事务日志总预算 64 MiB。记录开关、重启、丢弃或容量淘汰会影响覆盖。记录连续采集区间与已知缺口，旧库无法还原的时段显示覆盖未知。图中用空档区分「未采集」与「确认为零」。关闭后仍可浏览保留期内的数据，清空时同步清除可反推出域名、IP 的排行和缓存。汇总查询限窗口、限并发，用读快照或短时复用结果，避免全表计算长时间持有采集写锁。

**入口与验收。** 改动集中于 `SuiteDashboard.tsx`、`RecentQueries.tsx`、`diagnosticRoute.ts` 及对应测试。用固定记录覆盖跨桶边界、相似域名、相同时间戳、零流量、缺口和旧版记录。点击某桶某来源后，列表条数与汇总一致。使用接近容量上限的数据库测量首页刷新延迟、采集积压和磁盘使用。管理员可查看，沿用现有鉴权和角色限制，外部只读观察凭据无法读取域名和来源明细。

## B · AdGuard Home DNS 规则兼容

首版对外名称用「支持 AdGuard Home 常用 DNS 规则」。兼容承诺限于下表的 **QNAME 匹配语义**。首版统一采用本机 REFUSED 拦截响应，导入页明确显示该行为。不同 AdGuard Home 配置可能返回零地址或其他应答，验收分别检查规则判定和 LovestDNS 应答。

| 输入示例 | 首版处理 | 必测用例 |
| --- | --- | --- |
| `ads.example.test` | 精确拦截 | 本域命中，`img.ads.example.test` 通行 |
| `\|\|ads.example.test^` | 拦截本域及其子域，按 DNS 标签边界匹配 | 本域和 `img.ads.example.test` 命中，`badads.example.test` 通行 |
| `@@\|\|ok.ads.example.test^` | 普通例外优先于任意订阅的普通拦截，继续执行正常解析 | 在上一行生效时，例外域及其子域通行，兄弟域仍拦截 |
| `0.0.0.0 ads.example.test` | 接受指定阻断地址的 hosts 行，精确匹配；首版接受 `0.0.0.0`、`127.0.0.1`、`::`。支持别名和行尾注释 | 每个别名只匹配本域；其他 IP 的 hosts 重写行列为不支持 |
| 空行、`! 注释`、`# 注释` | 跳过，单独计数 | BOM、CRLF、大小写、查询名结尾的点均有样本 |
| 正则、通配表达式、元素隐藏、扩展修饰符（含 `$client`、`$dnstype`、`$important`、`$badfilter`、`$dnsrewrite`） | 显示原行、行号和原因；保留完整表达式供检查 | 受限规则不会被截断成无条件拦截；遇到无法执行的例外、禁用规则或预处理指令时，阻止候选订阅激活，以免扩大拦截 |

匹配时统一 DNS 大小写和末尾根标签；首版明确接受合法 ASCII 域名和已编码的 IDN A-label，其他形式报出原因。只检查请求名，响应中 CNAME 目标检查可在后续单独加入。订阅之间稳定去重并保留来源、原行和版本。相同判定有多条来源时，详情采用稳定排序。发布前用固定版本的 AdGuard Home 在隔离环境对照支持矩阵，保存版本、输入和对照结果，再用至少一份固定快照的公开 DNS 订阅列出实际支持、跳过、拒绝的数量。测试夹具遵循原列表许可。[AdGuard 官方 DNS 规则说明](https://adguard-dns.io/kb/general/dns-filtering-syntax/)

### 订阅与配置生效

1. 管理员可添加 HTTPS 地址、启停订阅、手动刷新或设置刷新周期，并编辑本地规则。首次导入先预览有效、重复、无效和不支持行数。普通不支持行需显式接受部分导入；自动刷新遇到新增不支持类型或受保护语义时保留上一版本，等待复核。空文件、HTML 错误页或整份无有效规则的结果拒绝自动替换。
2. 下载在管理任务中完成。限制响应大小、解压后大小、规则数、重定向次数和总时长。对用户提供的远端地址及每次重定向校验目标范围，默认仅允许公网 HTTPS；控制台隐藏 URL 中的敏感参数。复用合适的任务锁和下载原语，广告订阅维护独立版本，软件更新代理仍只处理软件发布物。
3. 候选规则经过规范化、冲突计算、编译和预检后写入不可变的版本目录。切换完整版本，加载后用受控域名实查拦截与放行并核对运行版本；成功后更新活动状态。失败恢复上一已验证版本。并发更新、重试、程序重启或中途中断均需能确定所用版本。本地例外和订阅更新通过同一版本检查串行应用，避免相互覆盖。
4. 「检查域名」使用当前活动规则快照，展示预期判定、匹配规则和来源。判定优先级为本地精确放行（含未到期的临时放行）、普通例外、普通拦截、继续解析。该工具独立于查询记录开关，结果标明「按当前规则测试」。

### DNS 执行位置

优先在现有分流模式的 MosDNS 入口编译精确域名集合、后缀域名集合及例外序列。在**入口缓存及正常分流之前**完成判定。命中拦截时直接结束请求，拦截应答绕开共享缓存；放行则继续原有 Hosts、分流与缓存流程。处理 A、AAAA、HTTPS、TXT 等查询类型，沿用现有 UDP/TCP 入口。过滤默认关闭，关闭时移除过滤分支。记录和面板停用时，已生效的 DNS 规则仍须工作。

实施前先核实原生与 Docker 最终渲染的模板、入口和缓存顺序。重点阅读 `integrated/runtime/configuration.py`、`packaging/native/adapt_upstream.py`、`packaging/integrated/patch_upstream.py` 和组件锁。当前 MosDNS 是冻结的定制组件，先以真实二进制验证现有匹配与拒绝动作。若要修改核心，先完成固定源码的可重复构建、既有分流对照和包内来源记录。纯递归模式 `CNAUTO=no` 直接进入 Unbound，首版仅提供解析可视化，过滤能力随实际入口返回；开启过滤的实例切换到纯递归前须明确提示过滤将停用。[仓库源码评估](paopaodns-source-enhancement-review.md) · [组件基线](../packaging/components.lock.json)

**B 验收。** 在确认为活动的服务入口，以 UDP/TCP 分别执行「先查询并预热 → 加入规则 → 再查被拦 → 放行 → 再查恢复」。直接查询服务以排除客户端缓存。用受控上游的请求计数证明拦截没有触达上游。另测同标签后缀、交叉订阅例外、自然 REFUSED、规则更新失败、旧版升级、关闭过滤后的原生分流和 `CNAUTO=no`。用同一负载对照关闭过滤、开启小列表和开启代表性大列表的 P95/P99、吞吐、内存及重载耗时，记录机器和样本条件。

## C · 从真实拦截记录放行

在日志详情中增加过滤判定、规则原文、来源、活动版本及时间。B 的编译阶段保留匹配索引。**历史命中需要请求执行时的判定。** 单凭 REFUSED、返回零地址、耗时，或按今天的订阅重算，都不足以确定某条历史请求被拦。

先用冻结组件做一个证据采集验证：在实际执行过滤的分支产生带活动版本的本机事件，验证能够唯一关联到记录。若现有组件无法可靠输出，改用固定源码的最小事件钩子。事件以实例、进程代次和请求标识区分，包含动作和匹配规则 ID；接收端按版本取规则，保证保留期内仍可读，或直接保存受限的命中快照。若要与入口报文配对，必须覆盖两个客户端同时查询同域、复用 DNS ID、重传、TCP 并发和丢事件；发生歧义时显示「未取得判定」。事件队列有界，过载时记录缺口并继续解析。关闭查询记录后停止持久化此类逐请求信息。

详情提供「精确放行 10 分钟」「永久放行此域名」及「重新查询」。首版放行作用于整个实例，按钮旁标明范围。临时放行以绝对到期时间存储，运行时按时失效，重启期间已过期的条目不得重新生效。成功提示以规则已应用为准；重新查询单独显示结果。概览可增加「已确认拦截」及来源排行，分母、采集缺口和未知判定明确可查。

**C 验收。** 一台测试客户端访问受控拦截域名，打开真实记录能看到正确的规则和订阅版本；临时放行后本域恢复，兄弟域仍受原策略约束，到期后自动恢复拦截。订阅替换后旧记录仍展示原判定。另测清空日志、进程重启、延迟事件，以及正常上游返回 REFUSED 的对照请求。

## D · 可选增强：逐请求分流路径

在 C 的事件机制上逐步增加已执行的分流规则、实际递归或转发、回退、缓存层。处理回退、并发分支时只展示可证实的路径。上游 ADDINFO 中可能存在缓存生成时的标记，复用响应前要验证其归属。此阶段单独验收冷热缓存、并发和回退；A 至 C 无需等待 D。[上游调试信息与缓存语义](paopaodns-source-enhancement-review.md)
