# DNSCrypt 缓存补丁扩展验证

从 `25c9169` 继续，只比较已锁定的 2.1.20 原实现与独立分片补丁，不修改补丁、组件默认入口或在用服务。41 使用新目录、独立网络命名空间；不操作 旧版正式机，不提 PR。

## 有限验证范围

1. 新增显式 `--cache-matrix` 诊断夹具，仅允许已锁定的 2.1.20。先检查真实插件的 miss/CD/DNSSEC 隔离、容量边界、正/负缓存、TTL/过期提示、EDNS 标志和并发响应所有权。原实现和补丁均运行契约及 race 检查。
2. 底层缓存补奇数容量、每个分片精确填满及全 visited 后淘汰检查。测试通过选键填满分片验证容量可用性，不把自然分布中的未满当成越界或故障。
3. 11 种负载 × 1/2/8 个工作协程，共 33 组；每组固定 100000 次，两个实现交错三轮，共 198 个计量记录组。负载包括四种空缓存容量、A/AAAA 单热点、四分之一/满容量、容量 17 的连续淘汰、90% 热键混合和过期提示。GOMAXPROCS=2，8 个协程不代表 8 个 CPU。
4. 每组单独记录进程 CPU、wall ns/op、分配、初始/最终条目及 hit/miss/stale/write 比例。热点必须全命中，空缓存必须全 miss，过期必须全 stale；其余场景保留实际比例，不要求不同随机分片映射有完全相同命中率。并发发生争用时只接受正确答案或合法 miss，不接受错答、越界或共享响应被修改。
5. 重新构建普通 upstream/cache 成对制品，核对既有二进制摘要。HTTP/1.1 与 HTTP/2、直连与实际 SOCKS、容量 1/17/512 验证真实缓存命中、淘汰和并发答案；另验证过期后重新回源。此部分为有限功能验证，不以未定速并发负载签署完整服务性能。

单个测试进程限时，编译与计量串行。临时 systemd 任务固定 CPU 4–7、400% 配额、1 GiB 内存、低优先级，并记录各步骤资源计数，监测在用服务 PID/重启、DNS 健康及可用内存；异常停止并保留失败。

微基准的计时包括实际缓存插件、固定的响应核对及工作协程调度，不包含网络；命中率/写入率不同的混合负载不能全部归因于哈希方法。结果不替代 UDP 补丁权限/内核组合、完整链路性能、打包升级回退和持续观察。

## 夹具修正记录

首次扩展契约在原实现的 EDNS 检查越界，未进入性能计量。原因是新库将 OPT 标志放入 `MsgHeader`、选项放入 `Pseudo`，夹具错误访问了旧式 `Extra[0]`。保留该失败树与日志，依据锁定源码修正夹具，新增显式 DO/UDPSize/版本/EDE 选项检查，在全新诊断目录重建；组件补丁没有修改，门槛没有放宽。
