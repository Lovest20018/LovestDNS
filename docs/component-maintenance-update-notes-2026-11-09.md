# LovestDNS 组件维护详细更新说明（2026-11-09）

**本轮测试源码与匹配整包已上传，Debian 12 原生隔离验收完成。** 更新集中在 DNSCrypt 的接收队列、报文分配与缓存开销，以及配置应用可靠性。源码、独立候选和测试工具已形成可核对记录；正式运行实例仍保留现有发布，这次上传用于构建和隔离验收。

## 1. 改了什么，用户会感受到什么

| 更新 | 具体改动 | 实际意义与验证范围 |
|---|---|---|
| UDP 接收队列 | 将强制 4096 字节接收缓冲改为普通 256 KiB 申请，由内核接收上限约束 | 修复有 NET_ADMIN 权限时队列反而缩小的缺陷；当前内核有限积压中，候选四种权限/地址族组合均保留 128/128 个问题 |
| UDP 报文分配 | 接收循环复用缓冲，收到问题后只复制实际长度；异步处理继续独占各自报文 | 减少小 DNS 问题的分配量。63 字节入口微基准约 4228 → 196 B/次；大报文收益较小，未据此宣称整机 RSS 下降 |
| 缓存分片哈希 | 对实际使用的 32 字节摘要直接哈希，移除十进制字符串格式化 | 局部缓存命中成本约 9 → 2.3 微秒，每次少 160 B、2 次分配；完整 DNS 解析速度仍需另测 |
| 配置应用争锁 | 已受理的维护任务有界等待最多 60 秒，覆盖自动重载原有 45 秒时限；最终忙时给出明确提示 | 修复配置保存后应用任务因自动重载持锁而在两秒后失败的问题；已通过真实锁占用回归及容器实际配置应用 |
| 原生验收兼容 | 支持指定 CPU/配额/内存、记录系统版本；修正早期 Python 3.11 解包兼容 | 可以在 Debian 12 的原生 systemd 路径完成独立实例的安装、升级、缓存及恢复检查 |

缓存补丁继续保留完整键比较、CD/DNSSEC 隔离、锁、容量/淘汰和响应深拷贝。改变的是进程内分片选择，不会直接转换或重写 Redis/Unbound 历史缓存。UDP 补丁仍受宿主接收上限影响，不能保证任意突发规模都不丢包。

本阶段沿用已有控制台。没有新增逐设备 DNS 历史、设备与域名关联采集或新的解析速度面板；这些功能不能由组件微基准替代。

## 4. 缓存和恢复具体证明了什么

原生检查使用全新独立实例，在 Redis DB 0/1 放入各自的受控 A/AAAA 和大小写记录。相同 A 名称在两库返回不同地址，核对数据库隔离；整实例重启后，检查第一次查询的 Redis hit/miss、正 TTL 与上游计数。

本轮六个保存、升级或恢复后的复用点合计 264 次查询，全部命中 Redis、零 miss、零回源；候选新写入的记录也在再次重启后命中。这比单看“RDB 文件还在”提供了更直接的复用证据，但合成新鲜记录仍不代表正式历史缓存全集。

实际安装器的恢复流程已验证：

1. 升级前保存一致备份；正常升级后保留实例身份、用户配置和旧 RDB。
2. 显式回退恢复旧发布、服务配置与升级前数据，同时另外归档候选写入的数据。
3. 内部摘要错误的包在停止或切换服务前被拒绝。
4. 可校验但实际 DNSCrypt 启动失败的包，在切换后触发自动恢复，旧 DNS 和旧缓存再次可用。

这些动作全部发生在新命名测试实例中。需要正式升级时，仍应先确定获准的发布包、核对摘要、保留一致备份，再按现有原生部署流程操作。**本次没有执行正式实例升级，也没有要求现在手工覆盖在用 DNSCrypt 二进制。**
