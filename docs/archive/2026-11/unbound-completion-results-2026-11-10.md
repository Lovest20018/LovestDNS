# Unbound 更新收尾及组合候选验收

按用户决定，DNSCrypt `2.1.20 combined` 纳入推荐组合；此前新旧性能对照的缺口继续保留。本轮范围见 [执行方案](unbound-completion-plan-2026-11-10.md)，基线应用代码为 `607a123`，组件为冻结的定制 MosDNS、Redis `7.2.17`、Unbound `1.26.2` 和 DNSCrypt combined。

全量历史回放与匹配原生组合的功能验收完成，严格容量阈值和 Unbound 性能关卡未通过；全部结果及证据已独立核对，默认组件和正式实例没有升级。

## 历史输入与比较范围

固定实际历史 RDB 副本共 **2,022,211 个键**：1,909,945 个可识别 DNS 值和 112,266 个删除标记；其中 20 个 DNS 键无法按提供的种子核对。所有历史 DNS 截止时间均已过期，未改报文、TTL、签名或写入／截止时间，也未向公网发送历史问题。

同一离线准备入口增加 **3,504 个别名**，准备后为 2,025,715 个键。既有目标、冲突组、CNAME 中间项与无法核对的条目保留。导出的完整问题目录含 **1,908,081 个问题**，DB 0 为 939,068，DB 1 为 969,013；5,348 次重复规范查找合并，11 个问题没有小写目标。计数按键、值和唯一查找分别统计，不能互相替代。

离线完整 DNS 解码确认一个 SOA 报文存在错误 RDATA 长度，但能导出完整问题。只有这一输入类别使用原始应答比较，要求事务、问题完整且新旧每个字节相同；不记作合法历史答案保留。其他输入比较 answer、authority、additional 的 RR 内容和重数、DNS 名称语义、不透明数据与 AD 标志；TTL 和名称展示大小写单独处理。回放明确启用立即返回过期记录、关闭预取和缓存写入，固定 Redis 7.2.17，使用普通 Unbound 1.21.1／1.26.2 和回环 SERVFAIL 夹具。结果限定为这份输入与该策略，不能扩展为任意历史缓存、DNSSEC 信任或生产时延保证。

四个有界工作线程经显式 TCP 完成 **1,908,081 个问题**，约 1,541.62 秒，**未解释差异为零**。以下为互不重叠的最终分类：

| 分类 | 问题数 | 结论 |
| --- | ---: | --- |
| 两版均保留原历史报文的 RR 语义 | 1,905,694 | 内容比较通过，历史时间未改 |
| 两版应答一致，但不等同于原历史报文 | 233 | 单列共同策略／部分应答，不记作原报文保留 |
| 缺失小写目标 | 11 | 两版均需刷新，固定 SERVFAIL 上游下未获得答案 |
| 完整问题可导出、原报文严格解码失败 | 1 | 两版均返回完全相同的 87 字节原始报文，不认定其合法 |
| 原写入时刻等于截止时刻的零寿命记录 | 2,142 | 旧版按历史语义返回，新版返回空 SERVFAIL 并刷新；保留为实际行为差异 |

两版相同结果合计 1,905,939 个问题，另外 2,142 个是上述已分类刷新差异。没有额外命中 CNAME 刷新差异豁免。新版普通可解码应答中，1,907,847 个的 answer／authority TTL 全为零，233 个含正 TTL；该计数不将任何过期输入重新认定为新鲜或可信。原始报文比较的一个条目不进入 TTL 语义计数。两数据库全部问题均完成，Redis 键数不变、零淘汰。

前轮失败均保留：首次在第 417 个问题发现零寿命行为差异；UDP 回放在约 2.18 万问题后出现传输错误，并记录一个负应答上下文差异，独立复现时新旧原始应答完全相同，前轮原因仍未确定。首轮串行 TCP 在 232,019 个已完成问题后遇到历史 SOA 严格解码失败；随后的四线程版本又在该条目的真实应答严格解码处停止。完成全量离线分类后，仅对此类输入增加原始字节比较，其余比较规则保持严格；没有静默重试传输错误。最终 TCP 完成不补签早先 UDP 失败。

## 当前模板容量、刷新和回退

读取当前生成模板的 `maxmemory=1572864000`（1,500 MiB）、`allkeys-lru`，在独立 Redis 副本上执行七阶段。原快照加载占用 901,921,770 字节，准备后 903,181,084 字节，增量 1,259,314 字节，加载和别名核对阶段均零淘汰。两数据库的受控两秒 TTL 答案先经 UDP 查询，过期重启后经 TCP 成功刷新，缓存写入时间增加。

随后写入 700 个 1 MiB 受控值，共 700 MiB。按每十次写入保存的样本，最高 `used_memory` 为 **1,607,391,543 字节**，比预算高约 **32.93 MiB**，超过预先固定的“预算加 4 MiB”阈值；Redis 自报峰值为 1,608,475,371 字节。写入结束即时记录 53,728 次淘汰，后续稳定检查时为 111,503，使用量降至 1,572,767,948 字节。该项**严格容量验收失败**，未更改门槛或用稳定后的占用覆盖压力样本。

在独立保护条件允许时继续完成 BGSAVE、压力后全量键／类型／值／DB／截止时刻摘要重载，以及原始快照完整恢复；三项通过，原输入和准备副本摘要保持不变。保存的压力快照为 1,372,503,279 字节，全流程约 214.92 秒。保存和恢复通过不会将整项容量改为通过。首轮在同一内存断言处停止且缺少细分压力计数，失败保留；补测只增加采样，并在保留失败结论后完成独立后续阶段。

## Unbound 性能关卡

固定 Redis 7.2.17，只比较 Unbound；性能任务与历史回放、容量准备串行。500 QPS、q64、串行上游、CPU 2–3、150% 配额、1 GiB 内存上限、Nice 10，先执行普通旧 Unbound 的 30 秒 A/A。

首对内存热缓存测量各 15,000 条查询，全部正确、零丢失，内核配对、socket／抓包及资源条件有效，没有 CPU 配额限流或 memory max／OOM 增量。P95 为 **0.592／0.594 ms**；P99 为 **1.390／1.093 ms**，差 **0.297 ms**，超过固定 0.2 ms 重复性门槛。

按方案立即停止性能分支。Redis 命中校准与四种场景的正式新旧交错矩阵未启动，没有追加相同条件的重复试验。此次无法建立有效对照，既不能据此认定新版性能回归，也不能签署无回归。原始 `redis-only` 标签在此表示“新版 Redis＋旧 Unbound”，没有把 Redis 差异混入本轮。

## 最终收尾

历史回放侧 **21 项保护检查通过**，原生组合侧 **20 项保护检查通过**。两边原服务进程与启动状态、发布制品、配置规则、身份账户、原备份、host resolver、系统启动标识和内核参数保持一致；原始快照、准备副本、目录和普通组件摘要保持。试验进程无残留，独立监视器停止，所有新建的具名命名空间已移除。

历史回放侧 **270 次**、原生侧五次尝试累计 **107 次**原服务 DNS 健康探测全部成功，逐次完整输出保留；两边收尾健康检查也成功。这只代表实际探测覆盖。历史回放侧独立心跳共 524,877 个样本，最大间隔约 62.56 ms，未用于过滤查询或签署性能。回放任务的 CPU 配额限流增量约 376.79 秒，memory max／OOM 计数无增量，cgroup 峰值约 1,151.70 MiB；有界功能回放不作性能测量。
