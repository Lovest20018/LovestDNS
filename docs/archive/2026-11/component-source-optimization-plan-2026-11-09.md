# 组件源码定位与定点优化

## 本轮边界

沿用 `codex/dns-core-upgrade-perf`，基线 `0ac77f0`。先定位 DNSCrypt 的额外开销，只有取得热点和正确性证据才加入运行补丁。MosDNS、Unbound 与正式环境默认组件不变；Redis 不追加同条件长压测。既有失败保留，详见 [补充验证](component-maintenance-validation-results-2026-11-09.md)。

## DNSCrypt：先分清构建、协议和代码成本

现场二进制 build info 表明：旧 2.1.5 使用 Go 1.22.5、PIE、CGO 和私有 musl；候选 2.1.20 使用 Go 1.27.3、普通静态可执行文件、CGO 关闭。新旧还存在 DNS 报文库、LRU / SIEVE 缓存及 HTTP 传输实现差异。此前 CPU / RSS 对照不是同一编译器下的源码单变量比较。

新增 `scripts/build-dnscrypt-diagnostic.py`：校验指定版本的完整上游源码归档摘要，使用指定 Go 版本和归档内 vendor 构建。只在新工作目录内添加诊断入口，产物名为 `dnscrypt-diagnostic`，清单明确 `diagnostic_only=true`、`deployable=false`；不写入组件锁或打包流程。诊断程序必须显式指定 loopback 地址和采样模式，否则启动失败。

新增 `scripts/profile-dnscrypt.py`：仅允许独立网络命名空间、新目录和摘要匹配的诊断产物。CPU / heap 分开运行，控制 TLS 证书、100 QPS、q64、唯一 A / AAAA 问题及缓存容量，校验 DNS 答案、丢包、实际路由、连接数和 HTTP 协议。CPU 输出 flat / cumulative 热点；heap 输出增量分配字节、分配次数及结束时存活堆。采样、强制 GC 与诊断构建都可能改变成本，因此结果只用于归因，不签署提速、RSS 回归或升级通过。

先检查以下路径：

1. TLS / HTTP 连接是否复用，是否出现大量新建连接或意外协议回退。
2. DNS 解包、打包、缓存键及缓存深拷贝的 CPU 和分配量。
3. 分配器 / GC 与运行时固定开销；不能将峰值 RSS 差异直接当作内存泄漏。
4. SOCKS 夹具的小报文转发与 TCP_NODELAY。先做只改变夹具变量的定向对照，不能把代理夹具延迟算成组件开销。

修补条件：热点能指向具体路径；补丁保持报文校验、DNSSEC/EDNS/TTL、缓存隔离和错误恢复语义；具备能发现错误复用或数据别名的针对性回归。若没有满足条件的热点，本阶段交付定位结果，不为了得到“改过代码”的结论撤销上游正确性修复。

首轮 CPU 诊断的一个约 0.6 秒调度间隔之后出现请求补发，解析端队列丢 37 包，保留为未通过。源码随后定位到新旧版 Linux 的 `SO_RCVBUFFORCE=4096`；确定性 128 包突发反例与独立补丁见 [补丁说明](../../../packaging/components/patches/README.md)。后续 CPU / heap 定位让两个原实现都去掉 NET_ADMIN，实测接收缓冲区，避免强制小队列混入对照；这是诊断条件变化，不追认首轮通过，也不修改正式性能协议。

诊断后用原版、未修改候选和必要的补丁候选做短范围验证。只有改动确实消除相应开销，才重新进入固定负载验收；不提高原性能门槛。

## Unbound：先确定迁移契约，暂不改查询热路径

`calc_hash()` 的大小写规范化属于上游修复。现有正式快照中可识别 DNS 条目全部超过报文 TTL；同名不同大小写键可能包含不同历史地址，另有 CNAME 中间结果。不能按 Redis SCAN 顺序覆盖成一个小写键，也不能把某个 cachedb 报文直接当作完整最终 DNS 答案。

后续离线兼容工具应遵守：

- 输入为不可变 RDB 副本和对应 seed / 配置；只连接工具自行启动的隔离 Redis。先输出只读计划，目标为另一份副本。
- 按 DB、原始 DNS 标签字节、类型、类和 seed 派生旧键与小写键，逐项核对。不能用拆分带点文本域名替代标签编码；不识别的压缩名、种子或报文单列跳过。
- 保留已有小写目标和全部旧键。多个旧键合并时，先比较答案及时间语义；无法确认等价的整个分组跳过，交由自然刷新，不能凭“较新”就选一个历史地址。
- 不改写 cachedb 的写入 / 到期时间、TTL、签名或安全状态；Redis 有过期时间时保留绝对截止时刻，不能因复制重新计时。过期记录不得被变成新鲜记录。
- 中间 CNAME、负应答、DNSSEC、非 A/AAAA、未知记录和非 DNS 键独立统计。初版不处理的类型必须报告覆盖缺口。
- 执行前重新核对源与目标指纹，冲突拒绝覆盖；原文件只读，回退仍使用升级前快照。新增小写键的容量和淘汰另验。

本方案编写时尚未实现迁移工具。后续已加入 [离线兼容准备工具](../../cachedb-offline-upgrade.md)与真实新旧版回放夹具，结果和仍保留的升级限制见 [组件收尾记录](component-closure-results-2026-11-10.md)。查询路径不做 Redis SCAN 或枚举大小写回退。

## Redis：仅在归因成立后修改

现有大 RDB 读取和全量内容一致性通过；旧版 A/A 的 P99 重复性未通过，尚未建立新版回归。下一次诊断需要分开记录 Redis 服务端命令耗时、Unbound 同步 Redis 等待及系统调度间隙。虚拟机停顿不能靠改 Python 控制层或随意调 Redis 参数消除。持久化重写、重载与回退仍属于独立兼容关卡。
