# home2 实例身份与构建来源

日期：2026-11-12。候选版本：`0.1.0-dev.lovestdns-native.20261112.home2`。本记录说明源码实现；最终安装包、部署和运行验收由后续结果记录单独说明。

## 页面行为

设置页展示持久实例 ID、服务单元、当前发布目录、配置/数据/状态目录和对应的绝对控制命令。命名实例不再显示默认实例的命令和目录。原生服务环境无法识别时，相关字段为“未记录”，复制维护命令的按钮不可用。

应用提交、前端构建提交与源码摘要、继承基础包版本/归档摘要、上游核心提交和组件版本声明分别展示。旧包没有应用来源时，不用上游提交代填。较长的摘要放在可用键盘展开的详情中；桌面两栏、手机单栏，保留明暗主题。

页面明确说明组件版本来自包内声明，当前页面未核对运行进程的实际文件。来源展示也不表示客户端查询路径、所有规则、长期稳定性或性能已验收。

## API 与安装记录

`GET /api/v1/capabilities` 增加可选的 `installation` 和 `provenance`，原有字段和权限保持兼容。响应只返回选定的非敏感元数据，不返回环境文件、Token、账户数据或完整来源清单。读取失败、格式无效、超过 1 MiB 的来源记录降为未知。

原生身份依据安装器约定的 `/opt/lovestdns[-实例名]/current` 服务环境识别，实例名限制与安装器一致。不会从网页 URL、显示名称或主机名猜测控制命令。命令生成器再次限制可复制的绝对路径。

新安装器将收据写到发布目录之外的 `receipts/<发布目录名>.json`，记录服务名、实际发布路径、版本、安装清单 SHA-256 和安装时间。只有经过摘要校验的 `upgrade` 路径记录外层归档 SHA-256；直接安装解压目录时保留未知。收据与当前发布的路径、版本和清单不一致时，API 不返回其中的归档摘要，页面提示待核对。

每个 release 使用自己的收据，回退后不沿用被替换版本的摘要。既有旧 release 没有收据时保持未记录。收据不加入被哈希的安装包，避免循环摘要。

更新后的根目录安装入口根据包内 `installation_receipt_v1` 能力标记调用新安装器的归档升级路径，兼容旧包原有参数。此入口会临时解压两份载荷，磁盘预算需要计入。首次从旧安装器升级时应使用更新后的入口；旧控制命令可能仍按旧逻辑安装，不能据此补造历史归档摘要。

## 实屏发现的长名称修正

home2 最终包已完成隔离安装/升级/回退并部署到测试实例。实际页面显示较长实例名时，侧栏网格的默认最小宽度会把状态标记挤出卡片。后续 `20261112.home2.1` 仅将名称列限制为可收缩宽度，并为完整名称增加悬停提示；增加包含中文的长实例名浏览器断言。

此修正不改变身份接口、收据、安装器、运行时和组件。最终制品仍需使用新的版本、提交和归档摘要，并通过逐文件差异核对、最终构建/浏览器检查、同包隔离升级/回退及实际部署验证；不覆盖已验收的 home2 归档。服务器浏览器因缺少中文字体产生方框属于截图环境问题，字体仅在私有验收目录提取和使用，不加入产品载荷或修改系统字体配置。
