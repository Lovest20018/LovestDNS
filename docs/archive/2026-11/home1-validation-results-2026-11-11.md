## 测试实例升级与接入范围

通过现有命名实例控制命令升级，生成停服后的 data/state/env/unit 一致备份和明确旧 release 回退点。备份的环境参数、手工配置、账户/身份摘要和旧 release 的 127 个载荷随后再次核对，回退材料可用；在用实例没有为演练而回退。最终包 150 个载荷与实际发布逐项核对，运行进程映射确认选定组件；网页实际引用的三个入口静态资源与构建摘要一致。外部 Token API 保持原先关闭状态，网页与内部采集仍可工作。

配置、账户、身份、网关文件/服务和标准 53 监听保持，两数据库抽样的无 Redis 到期时间字符串值，其类型和值摘要保持。该抽样不等于整库逐键验收，不将跨版本 DUMP 序列化字节当作唯一的数据语义。

升级前检查脚本曾将归档的无链接规则误用于已安装 venv，提前停止；修正为逐项校验安装包声明载荷后继续，未跳过任何载荷摘要，首次停止没有中断在用服务。

升级后从局域网发起 24 次 A/AAAA、UDP/TCP 查询，全部取得合法 NOERROR 应答：20 次有目标记录，4 次为同一样本的 AAAA 无目标记录，与前轮一致。报告保留 `passed=false`，无记录、超时和错误分开，不将其改报为全部记录可用。

随后持续 15 分钟，每 30 秒采集一次，共 31 次状态/资源样本和 DNS 探测，交替使用 UDP/TCP。所有探测成功，核心 PID 和服务启动标识保持、重启计数为零，未增加 OOM 事件，未出现持久化错误或采集陈旧；空闲磁盘始终高于 2 GiB 保护线。记录为功能观察，不提供高负载或响应分位数保证。

标准 53 仍由现有网关的 sniffbox 持有，运行快照所选上游仍为公网 DNS；候选在原高位端口提供服务。已完成服务端监听与局域网显式指定端口的检查，仍需核对标准端口的转发/接管策略并选择一台真实终端，才能进行系统 DNS 接入。逐请求来源 IP、域名历史、实际分流和全入口延迟统计仍属于后续观测阶段。

短期功能观察不证明长期稳定性、全量规则正确性或新旧性能无回归。[家用受控试验](home-use-results-2026-11-11.md)中的四次慢响应及历史性能停止结论保留；本轮没有重新展开微秒排名、改默认模板/预算或切换公开安装入口。
