## 真实核心与故障

| 验证 | 结果 |
| --- | --- |
| 原生及容器纯递归/分流模式 | 就绪、UDP/TCP 本地固定记录、两层 Unbound、实例身份和 Redis RDB 保留均通过 |
| 配置及历史 | 真实 HTTP 条件保存、旧版本拒绝、历史恢复及写入意图懒恢复通过；版本冲突遵循既有 **412** 契约 |
| custom_mod 应用 | 相同请求编号幂等，应用后查询命中目标记录；强制 MosDNS 启动失败后恢复旧运行配置及 DNS |
| 网页重启 | 成功约 **16.67 秒**；Web 和 manager PID 不变，Redis DB0/DB1 测试值及 UDP/TCP 查询保留 |
| 网页重启失败 | 强制 bootstrap 返回失败，约 **11.87 秒**返回失败任务；确认运行配置、DNS 和两套 Redis 数据恢复，Web/manager 保持运行 |
| 备份 | 成功及失败重启后保留两代清单，逐文件大小和 SHA-256 均匹配 |
| 管理进程终止 | 对正在执行快照任务的 manager 发送 SIGKILL；自动恢复后任务为 interrupted，同一请求编号不重放；六个合并请求编号在重启后仍返回原任务 |
| 采集器故障 | 原生及容器均在断连时返回 503/UNAVAILABLE，恢复后健康检查通过 |
| SQLite 写锁 | 独立临时目录中用真实 SQLite 写事务阻塞领取和结果入库；能力降级后可恢复，结果入库重试只执行一次动作 |
| 磁盘耗尽 | 独立 **2 MiB tmpfs** 在文件已写后达到真实 ENOSPC，确认 503/SAVE_UNCONFIRMED；释放空间后原文和候选版本均可恢复。未填满主机磁盘，临时挂载已卸载 |

首次补充验收脚本误将版本冲突断言为 409；按现有 412 契约修正后重跑通过，未为此修改产品逻辑。首轮四个冻结测试因上传时漏带冻结档案而未启动，补齐校验后的原档案后全量通过。

## 本次测量

| 场景 | 结果 |
| --- | --- |
| 六个未发完请求的本地 IPC 客户端存在时读取任务 | 最慢约 **17 ms** |
| 八并发、96 次真实读接口及本地固定 DNS 查询混合请求 | 总计 **0.724 秒**，P50 **56.6 ms**，P95 **71.9 ms**，最大 **76.3 ms**，全部成功 |
| 测量时整个原生 service cgroup MemoryCurrent | **177,913,856 bytes，约 169.7 MiB**；含 DNS 核心、Web 和采集等进程 |
| 四个文件、合计 96 MiB 的流式备份及校验 | 子进程峰值 RSS **38,544 KiB**，备份前后观测到的峰值增量 **0 KiB** |

这些数值属于本机短时样本，不是生产容量承诺，也不证明相对旧版本的延迟/CPU 改善。未执行外部慢 DNS 长时间压力、CPU 对照基线、跨 worker 诊断容量限制、cgroup 动态预算调整或生产安装器回退演练。
