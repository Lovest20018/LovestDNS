# Review 三项问题修复

本轮修复 `.opt3` 候选审查中复现的三项 P2，并补充可重复的 API、共享文档及浏览器回归。旧的 `.opt3` 验收数据保留在 [上一阶段记录](optimization-followup-2026-11-06.md)。

## 修复结果

| 问题 | 修复行为 | 回归覆盖 |
| --- | --- | --- |
| 文件保存后被外部工具改回原文，候选被删除 | 删除写入意图前始终将候选归档；若磁盘不等于候选，再记录实际磁盘内容。保留原文与候选，继续返回 SAVE_UNCONFIRMED，供用户核对 | 真实 Flask/v1 写入后外部恢复；意图恢复时原文件不存在、为空及普通原文 |
| 旧保存响应回退共享文档的 baseline/revision | 每个文件维护独立的基线代次。读取或保存接受不同基线时递增，普通输入保持代次；响应仅能更新它发起时的代次。实例 epoch 继续隔离退出和实例切换 | 两次保存响应交错、基线回到旧 revision、草稿失效、跨实例，以及保留保存期间的新输入 |
| 同页组件日志链接只更新 URL | 监听当前页面的 component 参数，切换组件并清除旧日志；下拉选择同步 URL，支持浏览器后退。自动及手动读取都带独立取消信号，切换和卸载会取消旧请求 | updater → manager 的同页链接、浏览器后退、下拉选择与日志内容一致 |

新增的浏览器场景会延迟一个已经在服务器提交的 PUT 响应，跨页重新读取并完成第二次保存后才放行旧响应，验证页面仍保持已保存状态，并能继续保存第三次修改。测试使用回环地址、合成配置和独立 Chromium profile。
