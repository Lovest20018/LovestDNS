## 验收环境与方法

使用仅有回环网卡的独立网络命名空间、合成域名与本地受控 UDP/TCP/HTTP/2 上游，不切换客户端 DNS。新测试实例的应用、数据和工作目录使用限容 tmpfs；分别限制 CPU 与内存。现有服务的进程身份、载荷、配置、实例和账户、备份、宿主机解析器及相关内核设置在前后核对，运行期间持续探测现有 DNS。

第一轮测试脚本将 tmpfs 挂在 `ip netns exec` 的私有挂载命名空间中，systemd 无法看到测试数据目录，安装健康检查未通过。这是测试准备错误；原始失败日志保留。停止该轮后，核对并清理其新建实例路径，再将挂载移到进入网络命名空间之前，使用新测试实例重跑。候选归档没有因此修改。

第二轮干净安装及查询采集检查全部通过；升级部分因测试数据目录只分配了 128 MiB，低于安装器另需预留的 256 MiB 与备份空间而被拒绝。保留该结果及清理记录，第三轮把测试数据目录限额提高到 512 MiB，只重跑升级和回退，干净安装证据仍对应同一份候选归档。没有降低安装器的空间要求。

## 干净安装

实际安装器完成离线安装；重新核对 158 个已安装载荷文件、配置恢复、来源信息和三类 DNS 组件实际持有的 UDP/TCP 监听。认证与只读权限、配置历史及恢复、幂等配置任务、MosDNS 配置启动失败后的运行配置恢复、Redis 后台快照和 observer 故障恢复均通过。错误版本的安装收据被识别为不匹配。

安装后的 `query-recorder` 独立运行，实际 systemd 单元含 `AF_PACKET` 地址族权限。33 次明确计数的查询验证：

- 默认关闭且没有历史，管理员之外的匿名和只读身份均被拒绝。
- 自动入口采集 20 条 UDP/TCP、A/AAAA 事务，来源地址、响应状态及耗时有效；事件编号不重复，类型筛选与七条一页的游标遍历完整。
- 停止采集器时 API 返回 503，DNS 仍能响应；重启后已存记录保留，采集会话编号变化。
- 停止 Web 时 DNS 和采集继续，恢复后能读取期间两条记录；重启整个原生服务后开关与 22 条记录保留。
- 改为手动递归入口，另外四条记录属于 `unbound-raw`；恢复原配置后返回自动入口。
- 关闭、清空和关闭期间不新增记录通过；最后保留一条记录用于后续数据核验。

这些是安装后的实际被动报文证据。逐请求缓存命中与分流路径字段保持空值。
