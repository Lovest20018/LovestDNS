# 独立 DNS 控制台 console4 候选收口

日期：2026-11-09。实施基线 `750ab5c`，目标版本 `0.1.0-dev.lovestdns-native.20261109.console4.1`。本轮先形成可日常试用、来源明确的控制台候选，再按独立关卡推进组件升级及新的查询观测。

## 本轮内容

- 保留 console3 的六入口、核心组件常驻、缓存统计、诊断、维护与历史，以及默认关闭的可选网关观测。
- 纳入之后的应用维护修复，重点复验配置保存、预览、应用任务及自动重载争锁。
- 统一源码版本、API 契约、前端构建清单和原生包来源；从干净的明确提交构建，记录载荷与整包 SHA-256。
- 使用官方原生打包与命名实例升级入口，在现有测试实例上保留配置、人工规则、身份、账户、缓存和网关联动，生成新的一致回退备份。

默认包不传入 `--components-bundle`：定制 MosDNS `240822.1`、Redis `7.2.5`、Unbound `1.21.1`、DNSCrypt `2.1.5` 及私有依赖继续采用固定上游来源。构建后逐文件核对组件与测试实例原发布完全一致。独立三补丁 DNSCrypt `2.1.20` 等制品保留候选身份，本轮控制台验收不批准其默认升级。

## 交付门槛

1. 冻结独立 WebUI 校验、前端源码测试、TypeScript/Vite/ESLint、Linux 后端与工具回归及 API 契约检查通过。Windows 回环受限记录继续保留。
2. 整包载荷可验证；前端与包内源码摘要一致，前端清单指向已提交且构建时干净的源码。
3. 升级前后核对配置、身份、账户设置、人工规则、网关配置、宿主解析器与核心依赖；新备份的 release 元数据必须指向升级前的实际版本，原有 console3 回退备份继续保留。
4. 通过 UDP/TCP、IPv4/IPv6、缓存与快照、日志、配置历史、任务幂等、浏览器会话/CSRF 和网关只读观测检查。临时认证会话仅在测试机本机使用，检查后撤销。
5. 配置修改和故障注入先在全新隔离实例中检查；现有试用实例执行保留原文的回归，不覆盖用户设置，不替换网关转发核心。
6. 完成有界低负载与两小时受控正确性检查，再按本轮变更范围记录测试实例观察。原定 24 小时观察已于 2026-11-10 经用户调整，不再作为本次固定核心控制台试用的必过门槛；实际 9 小时 11 分钟的记录及停止原因保留。单独报告查询结果、重启、采集缺口、内存与磁盘趋势；这不替代组件版本间的正式性能对照。

没有完成的门槛逐项列出。构建成功、升级健康和短时功能通过分别记录，不能据其中一项宣称稳定版本或整体提速。正式实例升级等待测试结果确认；本轮不更改正式实例，不推送源码或发布安装包。

## 后续主线

下一轮在该控制台基础上补足可核对的运行配置摘要与解析结构，完善“状态 → 日志/配置 → 保存应用 → 域名验证”。设备与逐请求观测先验证真实来源地址、请求/回答字段及采集预算，再决定有界存储和界面；DNS 解析证据、缓存来源和网关连接分别呈现。网关联动继续可选，原生 Debian 优先验证，Docker 保留兼容。

初次 console4 使用 `development-reuse` 前端依赖，锁文件复现生成的文件不同，因此不作为可交付包。修正版 console4.1 在原生打包入口提前检查依赖模式、干净提交、源码和锁文件摘要及完整产物，使用锁文件构建后重新进行安装、浏览器与持续运行验收。初次包和失败证据保留，两次运行时长不累计。

实测进度、包摘要与未完成关卡见 [console4.1 验收记录](console-validation-2026-11-09.md)；现场路径、配置、原始日志与凭据仅保存在忽略的私有证据目录。

本轮候选试用收尾完成：两小时诊断复验 138,787 次查询全部正确，短期观察 552 次主动 DNS 探测及 111 次 Web 检查正常，最终服务、配置、载荷、备份与私有证据核对完成。首轮负载的一次超时未归因，继续保留为未解决项；没有把后次通过改写为全尝试无失败、24 小时通过或容量验收。
