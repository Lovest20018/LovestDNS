# 源码与版本收口

当前源码、API 契约及默认构建版本统一为 `0.1.0-dev.lovestdns-native.20261109.console4.1`，用于独立 DNS 控制台的下一轮实机验收。它在 console3 界面与可选网关观测基础上纳入后续维护修复；默认原生构建继续使用固定上游组件，不传入独立组件候选。范围与门槛见 [console4 候选收口](console-candidate-2026-11-09.md)。初次 console4 因前端使用开发依赖复用而被拒绝，修正版要求锁文件构建及完整产物来源校验。既有 `.opt4`、`.opt5`、console1–4 及组件试验包保留原名、原摘要；不创建公开标签，不上传 Release。

## 版本来源

后端 `integrated/backend/server.py` 的 `VERSION` 是源码候选版本，原生打包默认读取它；前端从能力接口展示服务端版本。v1 契约的候选版本、OpenAPI 和合成样例同步生成，API 主版本仍为 `1`。`install.py` 的默认下载版本继续保持已发布的 `.11`，避免下载不存在的候选资产。测试包通过 `--package` 和 `--sha256` 显式安装。

本地提交定位命令：

```sh
git log -1 --format=%H -- docs/contracts/v1/manifest.json
```

构建从该提交的完整源码快照进行，不以测试机临时提交代替本地提交。前端 `build-manifest.json` 记录实际 `source_commit`、`working_tree_modified=false`、锁文件摘要、工具版本及前端文件摘要。原生包 `source-provenance.json` 与契约清单的源码摘要相同，`manifest.json` 校验全部载荷。

源码摘要包含 JavaScript、浏览器回归脚本、依赖文本和 PNG 资源；文本使用 LF 规范化字节，二进制资源使用原始字节。新增回归验证这些输入会进入摘要，并排除依赖缓存和构建输出。Git 提交覆盖全部受版本管理的文档，源码摘要仅覆盖清单声明的范围，两者配合定位构建输入。

## 备份与实机测试

更新前保留旧程序、配置、数据和状态，并核验备份摘要及恢复入口。真实服务升级使用原生安装器，安装器会另外创建停止服务后的回退备份；不删除旧发布目录和既有备份。

实机测试先记录现有配置与 DNS 结果，升级后核对版本、载荷、实例身份、账号状态、业务配置、DNS 查询和维护服务。故障注入、规则改写及主动回退演练继续限定在有标记的隔离实例，实际使用中的实例不运行这些专项。

此前 `.opt4` 的 306 项回归、浏览器及真实核心验收见 [Review 修复记录](review-fixes-2026-11-06.md)。`.opt5` 的构建和实机结果另行保存为本地验证材料；console1–3 见 [控制台实施记录](ui-console-implementation-2026-11-07.md)。现场地址、凭据、配置内容或迁移备份不进入源码提交。
