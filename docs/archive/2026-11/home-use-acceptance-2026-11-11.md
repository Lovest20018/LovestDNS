# 十台以内终端的家用验收

用户于 2026-11-11 明确项目用于家用，终端不超过十台，并同意把后续工作转向实用验收。后续组件默认选择以解析正确、稳定、配置与缓存可恢复、资源可控为重点；暂停追求微秒级版本排名和发生器调度归因。此前性能失败与未覆盖范围保持原记录，不改判为通过，也不再自动阻塞独立的家用功能验证。

本轮已完成：[30 分钟受控结果](home-use-results-2026-11-11.md)。18,854 条持续／突发查询全部正确，无超时或组件退出；四次超过 100 ms 的应答及约两秒的发送／心跳间隔均保留。结论限定为家用候选的有限功能验收。

Unbound [官方性能说明](https://unbound.docs.nlnetlabs.nl/en/latest/topics/core/performance.html)明确指出，多数用户通常不需要专门调优，大规模解析服务才更可能需要这些工作。因此，继续追求本项目旧版 A/A 的 0.2 ms 重复性，对当前家用目标的收益已经有限。这是结合使用规模作出的项目取舍，不是把组件性能问题认定为已解决。

## 保留的必要检查

| 内容 | 已有证据／剩余工作 |
| --- | --- |
| 分流、缓存、协议 | 已有新组合的受控分流、A/AAAA、UDP/TCP、DoH 直连／SOCKS 与真实 Redis 命中检查；补一次持续轻负载 |
| 数据兼容和回退 | 沿用新旧 Redis 大快照保存／重载／回退、Unbound 全量历史回放和原生候选 19 阶段；保留已分类行为差异 |
| 日常可靠性 | 新组合尚需持续轻负载验证，要求应答正确，无超时、组件退出或 OOM；资源占用和全部发送停顿如实报告 |
| 管理界面 | 沿用控制台功能、认证、配置应用及失败恢复证据，后续修改按具体功能回归 |
| 性能研究 | 原新旧版性能验收仍未完成；不再把亚毫秒排名作为这次家用候选试用的先决条件 |

十台设备不能直接换算成固定 QPS。下述负载是人为固定的合成场景，用于检查组合行为，不宣称等于用户家中的真实流量，也不据此宣布最大容量。

## 本轮唯一执行场景

复用已经核对来源的定制 MosDNS、Redis 7.2.17、Unbound 1.26.2 和 DNSCrypt 2.1.20 combined，不重新编译组件。只在新的私有回环网络和空目录运行合成问题，使用两层 Unbound 和 Redis DB 0/1 的分流链路，保持在用服务不变。

- 先按两条分流路径写入受控键，保存并重启 Redis／Unbound，确认首次查询从 Redis 重载；再检查 IPv4/IPv6、UDP/TCP、A/AAAA、两条分流和冷热问题的 32 个组合。
- 十个逻辑客户端连续运行 30 分钟：前 1,790 秒每个客户端最多每秒一次，最后十秒每个客户端最多每秒十次，合计目标约 10／100 QPS。按实际时刻发送，不突发补发错过的时隙；记录所有延迟、超时和发送滞后。
- 应答内容、事务与问题必须匹配；错答、超时、组件退出、OOM 或在用服务保护失败立即停止。两阶段各须完成至少计划数量的 90%，否则仅判负载覆盖不足；不通过同条件重跑选择通过结果。
- P50/P95/P99、超过 100／500 ms 的次数及最慢值用于说明实际体验；本轮不要求新旧版本相差小于 0.2 ms。整体受两核 CPU 配额、512 MiB 内存与 40 分钟时间上限约束，另有独立健康监视。
- 记录开始、运行中和结束时的进程、CPU、RSS、cgroup 内存及 OOM 事件；不以半小时的平稳表现证明长期无泄漏。结束后停止全部新进程，核对在用制品／配置与试验输入，导出合成查询和资源证据。

这轮只给出受控链路的家用候选试用结论，不替代真实局域网、路由器 DHCP 下发、公网上游可用性或长期使用观察。先前已验证的原生安装包与这里的组件摘要对应关系保留；本轮不自动部署到在用实例或发布稳定版本。
