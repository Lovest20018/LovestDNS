# 独立 Linux 主机的系统解析器试用

2026-11-11，在 home1 [组包、隔离原生验收和测试部署](home1-validation-results-2026-11-11.md)之后，从另一台实际 Linux 主机完成小范围接入验证。原 Windows 方案因 UAC 人工确认未完成，未切换其 DNS；相关临时规则已撤回。用户要求换设备后，改用远程可操作的 Linux 系统解析器。

## 方法和边界

客户端为另一台主机上的临时进程，使用 libc `getaddrinfo`。每次查询在新的私有挂载命名空间中，将单独的候选 resolver 文件绑定到该进程的 `/etc/resolv.conf`；网络空间保持原主机网络，报文经过真实局域网发送。宿主机 resolver、网卡/IP/路由和已有虚拟机不改。

服务端新增独立临时 nft 表，仅匹配选定客户端的接口、MAC、来源 IPv4，以及目标主机的 UDP/TCP 53，再重定向至 home1 原有高位入口。该表设置自动到期清理，并在试用结束后主动移除；既有 Gateway/Docker 表和 sniffbox 的 53 监听保持。

此试用确认第二台主机中、明确使用候选 DNS 的系统解析器进程可达和恢复，不代表整机、浏览器、手机或日常应用的 DNS 已切换。报文使用 IPv4 传输；AAAA 查询覆盖记录类型，不作为 IPv6 传输验收。Windows 之前的 IPv4/IPv6 显式查询检查与本轮范围分开。

## 实际结果

- 直接指定 home1 高位端口，以及经临时规则访问标准 53 端口，各执行 8 次查询；两域名 × A/AAAA × UDP/TCP，全部取得目标记录。
- 完整五分钟运行 21 次 libc 解析，交替两域名、A/AAAA 与 UDP/强制 TCP，全部成功，未省略或替换失败样本。每个子进程返回所用私有挂载标识、候选 resolver 摘要和宿主 resolver 保持结果。
- 使用两个唯一受控域名，分别核对 UDP/TCP。服务端短时采集仅保存明确测试域名的事件，按事务号、两端地址/端口和协议配对请求与应答；结合精确重定向规则、计数与 MosDNS 进程持有的 15453 监听确认该次路径。测试域名的 NOERROR 无地址记录如实记为无记录，未归为超时或常用站点可用性失败。
- 结束后，客户端宿主 resolver 的字节、inode、权限、网络配置与路由，以及主机管理服务、已有两台虚拟机的状态/PID 保持。全部临时查询进程退出，私有挂载空间释放。
- 服务端临时表移除、兜底定时器停止，原服务/核心进程、配置和非试用 nft 规则前后核对一致。没有重启在用 DNS 或 Gateway。

受控请求到达入口并取得应答，不证明具体规则、上游和缓存层命中；本轮不新增长期设备日志或持久 `client_path_verified` 状态，也不声称真实网页/应用已试用。逐请求分支仍按[后续观测规划](project-next-steps-and-ui-2026-11-11.md)独立实现。

## 保留的失败与恢复

首轮将 Windows 写出的 CRLF resolver 文件用于 Linux glibc，第一条 libc 查询返回临时解析失败，试验立即停止，宿主文件未变。改为明确 LF 文件后单条检查成功，再用新结果文件完整重跑五分钟；原失败方法、输入与结果保留。最终范围没有放宽。

备用设备的 SSH 超时属于连接不可达，不计作 DNS 失败；未启动/重启这些设备。原 Windows UAC 尝试没有变成已执行系统试用。

## 证据与后续

私有证据归档含 34 个索引文件，38,009 字节，SHA-256 `9c3fff8b09690501cf9a4b344fef09e7e5740b02295c8286b2606b34240ccf12`。导出时在远端逐项计算大小/摘要，取回后再次核对，并独立复算 21 次五分钟样本、两组各 8 次报文查询、两条 UDP/TCP 请求/应答配对、转发计数及保护状态。首轮失败和最终成功均保留。归档不含 SSH/MCP 凭据、账户库或真实缓存。

下一步可对用户选定的实际终端进行短期日常应用试用；如需长期使用，另行形成标准端口、DHCP/静态 DNS、IPv6 与恢复的具体配置。当前没有改变默认下载、长期网关规则或任何终端的持久 DNS。
