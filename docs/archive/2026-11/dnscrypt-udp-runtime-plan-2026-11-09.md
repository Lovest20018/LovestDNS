# DNSCrypt 普通制品 UDP 权限与接收队列验证

从 `178cedb` 继续，不重复因发送停顿中止的时延初筛。本轮验证 Linux socket 的确定性容量与普通制品权限行为，不测吞吐或宣布默认升级。

旧部署、2.1.20 upstream、buffer、udp、cache 五种普通制品分别覆盖 NET_ADMIN 有/无与 IPv4/IPv6，共 20 组。使用已核验制品与原锁，无需修改默认构建。UDP/cache 独立候选不代表三补丁组合已经验证。

每组执行：

- 新建隔离进程，核对实际进程能力和 `ss` 内核 socket 接收/发送容量、队列和丢包。
- HTTP/2 直连受控上游，先预热同名 A/AAAA，另用 4095 字节 EDNS padding 问题验证最大接收长度；所有答案核对交易 ID、问题名、类型、类、状态、地址及正 TTL。
- SIGSTOP 该隔离解析进程，在它完全停止后发送 128 个 256 字节有效 DNS 问题，再 SIGCONT 并检查答案。每包独立 ID；必须解释 `收到数 + 内核队列丢包 = 128`，拒绝未知丢包、重复/错答或未排空。
- 旧原实现和 cache（只有缓存补丁）在有能力时预期复现强制小队列、发生积压丢包；这是原缺陷的对照，不能称为正常负载下丢包测试通过。buffer/udp 在现有内核上限下应完整保留本次有限突发。
- 积压组和最大长度复查应零回源，启动及 A/AAAA 预热的实际 HTTP/ALPN 另计，避免把上游网络或 TLS 调度混入 socket 队列验证。

读取现有 `rmem_max/rmem_default`，另用测试自身 socket 申请 4096/65536/262144/1048576 字节，核对普通 SO_RCVBUF 被内核上限约束以及 Linux 的双倍报告值。不写任何 host 或 namespace sysctl，不将不同请求值说成覆盖了不同内核配置。若未来内核上限过小，补丁仍可能无法保存该突发，本工具应拒绝完整通过。

只在 41 的新目录和独立 network namespace 执行，限制任务 CPU/内存/总时长，监测在用 DNS 服务和可用内存；记录前后在用制品摘要及 sysctl。没有 NET_ADMIN 或 IPv6 的环境不能默默跳过并宣称完整覆盖。计量条件或未知功能检查失败即停，保留原因；工具明确 `performance_acceptance=false`、`release_approved=false`。

不修改上游补丁、组件锁和安装流程，不操作 旧版正式机。新旧内核、低 rmem_max、完整组合的打包升级/回退、长时间运行及严格性能验收仍分别判断。
