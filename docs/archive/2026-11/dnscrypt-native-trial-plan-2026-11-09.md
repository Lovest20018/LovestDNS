# DNSCrypt 组合原生整包隔离验收方案

从 `cb30cbe` 继续。只验证 DNSCrypt 组合在 Debian 13 amd64 原生安装、升级、缓存持久化和回退中的行为；默认组件锁、在用测试实例、旧版正式机 和 PR 均不改变，不运行性能测量或长期观察。

1. 校验 41 上已归档的旧原生包及普通 combined 候选，按新入口 `build-dnscrypt-native-trial.py` 生成匹配的 control/combined 包。两包共用当前 backend/runtime/installer，沿用原包的前端、wheels、模板和旧组件载荷；combined 仅额外替换 DNSCrypt 启动包装器及新增可追溯静态制品。原始来源、覆盖代码、锁和补丁另存清单，全部标记为未批准发布的测试包。
2. 使用全新的命名实例、数据目录、私有临时目录和仅 loopback 的 network namespace。systemd drop-in 固定该 namespace 和资源上限；安装器及健康检查从同一 namespace 执行。先装 control 并测试递归模式，再启用分流模式。受控本地 DNS、TLS DoH 和实际 SOCKS 夹具提供答案，不访问公网解析器。
3. 通过旧 Unbound/Redis 两个数据库写入相同名称的 A/AAAA，包含混合大小写；A 在两库返回不同地址以检查隔离。保存快照，重启后检查首次查询确实从 Redis 读取，零上游访问。另保存两个数据库的用户标记、配置标记和实例身份。测试数据为新建合成数据，不代表真实旧缓存全集。
4. 使用实际归档升级入口切换到 combined。核对正在运行的 DNSCrypt 制品摘要和版本、其他核心/依赖不变、用户配置与身份保留、RDB 复用及更新后再次保存/重启。检查实际直连和 SOCKS、HTTP/ALPN、UDP/TCP、上层热缓存行为和基本管理/观测 API。
5. 显式回退，验证恢复升级前原始配置、数据和 control，候选生成的数据被归档而非覆盖原备份。再分别提供校验失败的包和可校验但 DNSCrypt 启动失败的包；确认前者切换前拒绝，后者自动恢复旧服务及备份。故障注入只针对该新实例。
6. 结束时停止并禁用测试实例，确认无临时组件残留；保存配置/数据摘要、清单、安装/升级/回退日志及健康记录。核对原在用服务 PID/重启数、当前目录与运行组件摘要、host resolver/sysctl 不变。保留测试备份和唯一证据，不清理在用数据。

过程有限执行；功能或身份检查异常即停止并保留原日志，定位工具、配置或组件原因后再决定后续，不追改失败记录。安装前核对依赖齐全，不允许该轮触发系统包升级；限制临时任务 CPU/内存/时间，要求主机可用内存与磁盘均有余量，持续探测在用 DNS 服务。

本阶段成功也不代表 Debian 12、容器版、多内核、所有生产自定义配置、完整历史缓存、吞吐/尾延迟、两小时负载或 24 小时观察已验收。失败恢复与安装路径的结论按实际检查范围记录。
