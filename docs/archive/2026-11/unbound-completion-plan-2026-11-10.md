# Unbound 更新收尾与推荐组合

日期：2026-11-10，基线 `607a123`。用户决定将 DNSCrypt 2.1.20 combined 纳入推荐组合，继续完成 Unbound 后一起推进。推荐组合为冻结的定制 MosDNS、Redis 7.2.17、Unbound 1.26.2 和 DNSCrypt 2.1.20 combined；只有实际完成的验证才记为通过。DNSCrypt 的推荐决定不将尚未完成的新旧性能对照改写为通过。

## 本轮范围

继续使用现有测试环境和新的隔离目录，不操作在用 Redis、不修改正式配置或覆盖旧快照。复用摘要固定的实际历史 RDB 副本、普通组件制品及既有缓存兼容工具；保留当前规则、身份、账户、备份、host resolver 和内核参数。最终在全部组件状态明确后，构建匹配整包并完成隔离安装、升级、缓存及回退验收；不自动推送或公开发布。

## Unbound 剩余工作

1. 全量分类历史快照。对每个键和值核对格式、问题类型、类、时间及新旧键；将删除标记、未知结构、种子不符、CNAME 中间项与合法 DNS 应答分别统计。先确定各类实际覆盖，不能把旧报文 TTL 已过期解释为新鲜缓存，也不向公网发送历史问题。
2. 在分类结果上固定真实应答回放范围和比较规则，再运行普通新旧 Unbound。保留原字节和时间，区分直接命中、过期应答、合法刷新和确实不兼容；UDP 截断按 TCP 回退核对，CNAME 与负应答按各自语义处理。私有域名与明文缓存不进入公共报告。
3. 使用当前模板的 Redis 内存上限与淘汰策略，在独立副本上核对准备前后占用、别名增量、真实读取、刷新与保存；另以受控写入验证容量压力下的淘汰和恢复，原快照为回退依据。
4. 固定 Redis 7.2.17，只改变 Unbound，执行有界的新旧性能检查。沿用 CPU +5%、RSS +10%、P95/P99 增量不超过 `max(较小值×5%, 0.2ms)`；记录所有答案、逐请求时序和资源事件。先校准再交错比较，不能通过重复相同失败试验挑选结果。无法建立有效对照时如实保留缺口，不签署性能无回归。

## 资源与停止条件

历史数据检查使用独立网络命名空间、Unix socket Redis 和有界 CPU／内存／时长，只与 loopback 夹具通信。准备阶段先在命名空间外保存保护快照，再进入隔离环境。独立生产探测与心跳在另一 CPU 组保留完整结果；原服务或系统启动标识改变、连续两次生产 DNS 探测失败、可用内存低于 1 GiB 或磁盘余量低于 2 GiB 时停止整轮。单次探测失败亦保留。

每一阶段在运行前记录其实际输入、命令、资源上限和完成条件。检查后停止试验进程与命名空间，重新核对全部保护对象、来源摘要和原快照，下载并复核证据。单一快照、受控夹具和有限窗口的结果均按实际范围说明，不扩展为任意历史缓存或生产负载保证。

另在现有 41 测试机建立全新的原生组合试验实例。对照和组合均以已核对的 console4.1 基础包及相同的当前应用代码生成，界面与 wheels 保持原包字节；组合加入已冻结的普通 Redis／Unbound 制品和 DNSCrypt combined，包内明确记录基础包、应用覆盖、组件来源以及未接受的性能和容量边界。该包是可评审的隔离候选，不因成功构建而成为默认发布。

原生试验控制器使用 CPU 4–7、200% 配额、2 GiB 上限、Nice 10、最多 1800 秒；新服务另以同 CPU 组、150% 配额、1 GiB 上限运行在仅有 loopback 的独立网络命名空间。复核当前测试服务、配置、身份、账户、规则、备份和 host resolver，保留完整健康输出，沿用 1 GiB 可用内存及 2 GiB 磁盘余量停止线。执行干净安装、受控缓存保存、离线大小写准备、组合升级、导入准备副本、真实 Redis 命中及两数据库隔离、UDP/TCP 与加密分流、候选快照重载、显式回退、坏摘要拒绝和启动失败后的自动恢复。原始回退快照不被准备副本覆盖；完成后停止新实例并移除其命名空间。

## 固定性能矩阵

沿用已核对的冻结基准方法、普通 dnsperf 与串行上游夹具，500 QPS、q64、CPU 2–3、150% 配额、1 GiB 内存上限、Nice 10。Redis 始终为 7.2.17，对照只改变 Unbound 1.21.1／1.26.2；现有 `redis-only`／`combined` 标签按实际版本解释，不把 Redis 差异混入本轮。

先在内存热缓存与 Redis 命中入口各运行三对旧 Unbound A/A，每组 30 秒，任一测量、资源或 P95/P99 重复性失败即停止性能分支。两项校准通过后，内存热缓存、Redis 命中、全冷转发及 50% 混合数据集各运行 120 秒、五轮新旧交错，保留全部四十组。每组单独保存资源前后计数，内核完整配对、正确答案及零 socket／抓包丢失均须满足；Redis 准备查询亦要求完整配对。CPU 配额限流、memory max 或 OOM 增量非零时不接受该组。

单组校准最多 240 秒、正式组最多 420 秒，性能任务最多 10,800 秒。历史回放和大快照准备与性能测量串行执行，避免本轮工具相互争用。报告将原始组标签映射到固定 Redis 下的新旧 Unbound，原始记录保持不变。

## 历史回放差异分类补充

首轮在第 417 个已核对查询发现应答差异后停止并保留。该条目的原始写入与截止时间完全相同，新版日志确认外部缓存读取成功，随后因原始 TTL 为零未进入内部消息缓存，再向固定 SERVFAIL 上游刷新；旧版直接返回零 TTL 历史答案。这是实际行为差异，不能按字节兼容检查直接签署无变化。

后续全量回放保留原报文、时间和两版普通制品，将零寿命记录、缺失小写目标和不含终点类型的 CNAME 中间项分别计数。只有“旧应答精确匹配历史语义、新版返回无答案的 SERVFAIL”，且输入确属零寿命或 CNAME 中间项时，才标记为已分类刷新差异。比较仍区分 TXT 等不透明字节、负应答 authority、答案重数和 AD 标志；其他差异全部列为未解释。全量读取完成且没有未解释差异才能关闭此项兼容调查，已分类刷新差异也必须在结果中保留。受控新鲜答案与过期后成功刷新另以可应答的回环夹具验证。

第二轮 UDP 在约 2.18 万条查询后出现传输错误，另记录一条上下文中的负应答差异；该负应答在全新实例单条复现中，两版返回完全相同的报文字节。后续使用显式 TCP 传输回放全部可导出问题，保存结束前的组件存活状态和资源数据。TCP 检查的结论限定为该传输与输入；不能补签前轮 UDP，也不将单条复现解释为前轮原因已确定。

首轮串行 TCP 完成 232,019 个问题后，遇到能导出完整问题、但 SOA RDATA 长度不被完整 DNS 解码器接受的历史条目而停止。该条目没有进入新旧查询比较，不能据此认定组件错误。先用同一完整解码器离线检查整个固定目录，再进行四个有界工作线程的 TCP 回放。完整问题可导出但预期报文不能完整解码时，仍向两版真实实例查询并比较应答，只计入该输入类别；不把它计作原报文命中，也不允许刷新差异豁免。不能导出完整问题、截断目录或超过预算时继续拒绝。全量输入类别、原失败和覆盖限制均保留。

全量离线完整解码确认只有一个上述条目，四线程回放在旧版实际应答的严格解码处再次停止。该条目的独立原始 TCP 采集显示，两版均读取 Redis，返回的 87 字节应答完全相同。后续仅对离线预先识别的这一类输入使用原始报文比较：先验证事务 ID、应答标志及完整问题，再要求两版每个字节完全相同，不忽略 TTL、标志、authority 或不透明字节；任何差别仍计作未解释，且不计作合法历史答案保留。其余输入继续使用完整解码和原有 RR 语义比较。连接按数据库首次实际查询时建立，避免在另一数据库回放期间提前建立的空闲 TCP 连接失效；不静默重试传输失败。

容量首轮在受控大值写入时未满足“Redis 使用量不高于内存预算加 4 MiB”的预设断言，失败点未保存细分计数。补充运行保持原预算、负载和阈值，按十次写入保存一次使用量、淘汰计数和总写入量；即使观察到阈值违反，也将其明确记录为不通过，在保护条件允许时独立完成后续保存、重载和原快照恢复，不将后续成功改写为整项容量通过。

原生组合试验在完成显式回退及坏摘要拒绝后，因磁盘余量触及 2 GiB 停止线而中断，原失败及已完成阶段保留。随后对已停止构建的重复 Go 工具链逐文件核对内容、模式及所有者，仅将完全相同的文件改为共享硬链接，保留全部路径、源码及字节，并再次核对原服务保护对象。磁盘余量恢复到 3 GiB 以上后，以相同组件包、查询方法和停止条件，在全新实例继续完整安装至启动失败恢复验收；不降低磁盘停止线，不将中断的前轮记作通过。
