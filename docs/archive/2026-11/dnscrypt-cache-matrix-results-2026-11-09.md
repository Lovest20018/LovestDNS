# DNSCrypt 缓存补丁扩展结果

从 `25c9169` 继续。分片补丁本身没有修改；本阶段补了未命中、容量、淘汰、过期、负缓存和并发的验证工具。局部收益在这些受控负载中仍然存在，不能据此签署整机 DNS 加速或默认组件升级。

## 固定工作量对照

锁定的 2.1.20 原实现与分片补丁均使用 Go 1.27.3、原有缓存插件和 vendor。新增显式 `--cache-matrix`，不改变原先诊断构建的默认测试集，也不接受旧版本误用新版夹具。

11 种负载 × 1/2/8 个工作协程 × 两种实现 × 三轮，共 **198 组、1980 万次计量操作**，每组固定 100000 次，不含框架预热。两种实现交错运行，结果全部保留。GOMAXPROCS=2，因此 8 个协程不代表 8 个 CPU。

计量包含真实缓存插件、响应核对和协程调度，不含网络或完整 DNS 转发。每个操作核对应答的域名、类型、类、ID、TTL；每组核对总操作数、容量和实际 hit/miss/stale/write 比例。空缓存必须全 miss、单热点必须全 hit、过期组必须全 stale。未发生错答或容量越界，六个计量进程的 CPU 配额限流、OOM/oom_kill 增量均为零。

下表单位为 **进程 CPU µs/op，中位数**。p1 为一个工作协程，p8 为八个工作协程共享两个 Go 调度处理器；并发 CPU 是所有线程 CPU 时间之和，不能按它直接换算吞吐：

| 负载 | p1 原版 → 补丁 | p8 原版 → 补丁 |
|---|---:|---:|
| 空缓存，容量 512 | 8.128 → 1.319 | 8.687 → 1.601 |
| A 单热点命中 | 9.030 → 2.439 | 10.200 → 3.168 |
| AAAA 单热点命中 | 9.163 → 2.560 | 10.756 → 3.506 |
| 四分之一容量，128 键 | 9.403 → 2.783 | 11.088 → 3.324 |
| 512 键预填，容量 512 | 9.562 → 2.811 | 11.934 → 3.553 |
| 连续淘汰，容量 17 | 18.055 → 4.367 | 19.274 → 5.345 |
| 90% 热键混合，容量 512 | 11.124 → 3.561 | 11.334 → 3.625 |
| 过期缓存提示 | 9.655 → 3.109 | 10.782 → 3.527 |

空缓存容量 1/17/4096 和 p2 的结果也完整保留。33 种场景的三轮 CPU 中位数均下降；这个观察不保证每一轮的墙钟性能，也没有改变上一阶段完整服务测量仍未通过的结论。CPU 使用 `getrusage(RUSAGE_SELF)`，与 Go wall ns/op 分开，仍受频率、迁移、GC 和同机负载影响。

单热点命中从 432 B / 5 次分配降到 272 B / 3 次；空缓存 miss 从约 158 B / 2 次降到 Go 报告的 0 B/op、0 allocs/op。不同摘要的十进制字符串长度不同，格式化路径的 B/op 不恒为 160，不能将上一阶段单键的字节收益直接推广到所有键。

## 命中率、容量与正确性

补丁改变的是进程内分片映射。每个进程用随机 maphash 种子，因此不能要求不同进程中同一批键有相同占用率；并发会再改变访问次序。

- 512 键各写一次时，部分分片先满、其他分片有空位，原版和补丁都可能提前淘汰。p1 实测命中率中位数分别约 **94.14% / 93.36%**，没有将少命中的工作量算成纯 CPU 优化。
- 容量 17 连续淘汰组，p8 命中率约 **7.68% / 10.19%**；冷热混合组 p8 约 **94.23% / 94.07%**。保留每轮实际读写比例；这类负载的总 CPU 差异包含分布与调度差异。
- 底层缓存通过选键逐个填满分片，确认配置容量 1/2/15/16/17/33/512/4096 均可用满。全 visited 后继续插入仍会先淘汰，不突破容量。自然随机分布未填满与容量实现错误分别判断。
- 两种实现各通过 9 项普通诊断契约，新增 5 项分别带 race 通过；底层原实现 3 项、补丁 5 项带 race 通过。覆盖 CD/DNSSEC 键隔离、正/负缓存、截断和 SERVFAIL 不缓存、TTL 钳制、过期只提供 stale 提示、刷新替换、EDNS DO/UDPSize/EDE、响应克隆及并发所有权。

首次契约在 EDNS 夹具越界，未进入计量。已核对新版库的头字段/Pseudo 表示并修正夹具，保留原失败目录、日志和输入；组件补丁、验收门槛未修改。工具 Python 定向回归 22 项通过。

## 普通制品验证与收尾

普通 upstream/cache 制品成对重建，二进制摘要与上一阶段完全一致。HTTP/1.1、HTTP/2 × 直连、实际 SOCKS × 容量 1/17/512 × 两种实现共 24 组；再加两组 HTTP/2 直连短 TTL 验证，共 **26 组、13062 次查询**全部通过。

- 每个容量组 544 次查询：96 个不同 A/AAAA 键及各一次大小写命中，共 192 次；再次遍历 96 键；8 个客户端各 32 次混合查询，共 256 次。逐个检查交易 ID、类型、类、答案、域名、非零 TTL 和实际 TLS/ALPN/HTTP/路由。
- 容量 512 的八组都保留了二次遍历的 96 次命中；并发段中每组 192 次命中、64 次独立新键回源。小容量允许发生淘汰，并单独保留实际回源计数，不以期望命中率替代正确性检查。
- 两个短 TTL 组把缓存上限设为 2 秒，各验证首次回源、立即命中、等待 2.2 秒后重新回源。该检查不将上游健康时的过期刷新等同于上游故障时的 stale 回退验收。
- 普通制品未加入 profiling 或 race。以上为功能和有限并发验证，没有定速输入及正式延迟分位数验收，不能把它算成完整服务性能通过。

两次成功临时任务均已结束，无候选进程残留；最初失败的夹具任务与输出另行保留。包含失败阶段在内共 63 次运行中 DNS 健康探测均成功，最低可用内存约 5904 MiB。在用服务仍为 PID 1047426、NRestarts=0，公开域名解析 NOERROR；当前链接、在用 DNSCrypt 包装器、真实二进制及私有库摘要与既有清单一致。构建/race 检查阶段有配额限流和内存回收，普通功能阶段另有 4 次配额限流；所有步骤均无 OOM/oom_kill。只有六个成本计量步骤是零限流，普通功能段因此也不用于性能比较。

  --source-archive /inputs/dnscrypt-2.1.20.tar.gz \
  --toolchain-archive /inputs/go1.27.3.linux-amd64.tar.gz \
  --work /tmp/cache-matrix-upstream --case new-newgo --cache-matrix

  -test.run='^$' -test.bench='^BenchmarkCacheMatrix$' \
  -test.benchmem -test.benchtime=100000x -test.count=1
