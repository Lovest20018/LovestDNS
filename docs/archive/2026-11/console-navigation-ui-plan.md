# LovestDNS 控制台修改方案

基线为 v0.2.1（`b54675e`）。界面范围为原生版和集成容器共用的 `integrated/frontend` 控制台。来源设备备注涉及实例存储及管理接口，白名单订阅涉及策略编译、匹配与命中记录。已走读六个一级入口，对照本版桌面和手机截图，并在本地隔离实例用合成数据复现第一批表格中的四条路径。旧独立 WebUI 及安装包升级机制沿用现状。

## 全栏目功能归属清单

按 v0.2.1 的侧栏、独立子页面、详情和操作按钮逐项核对。下表给出实施后的主要位置；“快捷入口”复用同一编辑器或详情。同一条规则、一个设置项或一次后台任务只有一份数据。标有“新增”的功能属于本次方案。

系统设置与维护共用下划线页签，桌面和手机都直接展示可访问的功能。保留域名分流与运行参数的一次点击验收。表中的功能以当前权限、部署方式及实例能力决定可见性，现有旧链接仍按后文的兼容约定处理。

**交付核对。** 除下文的返回路径外，在本地夹具补查四组容易串栏的操作：强制转发列表 → 对应上游 → 返回原文件；指定组件告警 → 对应日志 → 原状态；网关联动连接测试 → 网关观测及 FakeIP 查询 → 返回原设置；软件更新改代理 → 检查版本 → 广告订阅页核对独立的刷新状态。每组记录起点、实际落点、返回后的筛选或草稿；原生、容器、受限权限及关闭可选功能时分别核对入口。此表为源码盘点与设计，新增路径在实施阶段验证。

**实现入口。** 在 `App.tsx`、`useDiagnosticRoute.ts` 和 `diagnosticRoute.ts` 上扩展现有 hash 路由。显式链接中的分区、筛选、时段优先，浏览器历史项保存来源列表的快照、页游标、事件 ID 及滚动位置。恢复滚动和焦点要等列表加载。历史项仅用于当前实例和角色。直接打开链接时用链接本身能确定的状态，缺失信息按该分区默认值处理。

`QueryAnalytics.tsx` 已能向下钻链接传递 start、end、snapshot，保留这部分。处理返回时同时覆盖首页及过滤页共用的 `BlockedQueries.tsx`，以及 `RecentQueries.tsx` 的重新查询入口。对无时段的实时列表单独验证新增记录期间翻页和返回的行为。`FilterProvider.tsx` 已为本地规则保存草稿，新增订阅可复用实例级内存生命周期，订阅地址可能含访问参数，不写入 URL 或持久化存储。已清空、已提交和待复核分别处理。

## 第二批 · 页面归属和动作落点

### 一级导航与配置归属

侧栏顺序调整为「概览、域名分流、查询与诊断、广告过滤、维护、系统设置」。原「解析配置」侧栏位置用于「域名分流」，原「设置」扩展为「系统设置」。宽屏点击侧栏、手机打开导航后点一次，即进入目标编辑器。管理员桌面验收以从概览到分流编辑器、从概览到全局参数各一次点击为准。

| 入口 | 默认落点及内容 |
| --- | --- |
| 域名分流 | 直接打开现有列表编辑器，转发、递归、DNSCrypt 等按文件切换。仅在当前实例会话内记住上次编辑列表；显式文件链接优先，首次使用沿用现有默认列表。规则页提供“分流模式与上游”链接，返回恢复原文件、草稿和编辑模式。 |
| 系统设置 | 有配置权限时默认打开原基础设置编辑器，命名为“运行参数”。现有搜索和六组参数保留，包括 CN 分流、IPv6、自定义转发和调试。分流模式和上游在此维护，每域名规则在“域名分流”维护。 |
| 系统设置中的其他入口 | 直接展示配置状态与应用、TTL 规则、高级配置文件、软件更新、服务信息、外部接入和来源设备。网关联动按勾选状态展示。无配置权限时默认显示服务信息。 |

保留原配置状态及差异、应用、验证区域。`#/config?tab=apply` 等链接继续定位到相应区域；`#/env` 显示系统设置的运行参数，`#/lists?file=…` 直接打开对应列表并高亮域名分流。为新的系统设置默认页和旧“服务信息”书签分别指定落点，保留 `#/deploy` 和 `#/settings` 原有服务信息语义。顶部标题、页签、面包屑和侧栏按同一归属显示。设置页签深链应支持刷新和浏览器历史。

验收两条编辑路径。第一条从概览进入域名分流，换列表、编辑、去检查 CN 分流模式、返回、保存，再按已有流程查看差异和应用结果。第二条从概览进入系统设置，修改运行参数、切到高级源文件，核对共享草稿、已保存目标和实际运行值。导航及切换文件均不得隐式提交配置。

| 区域 | 修改 | 验收路径 |
| --- | --- | --- |

过滤任务提出请求后可能跨页。`filterApi.ts` 的提交与轮询目前在同一调用里，调用页卸载会停止观察。把已受理任务的 ID 和读取结果交给实例级 FilterProvider 跟踪；回来时复核任务阶段和活动版本。拿到任务编号后只恢复读取，避免重复提交。接口返回前断线、无法确认受理时，展示待核对状态并刷新服务端任务列表。验收成功、失败及切页三种路径。该项来自代码走读，执行时先在延迟响应的本地夹具复现。

### 手动添加放行域名

在「广告过滤 → 放行列表」的列表上方提供域名输入框、时效选择（10 分钟或永久）和「添加放行」。空列表也显示此入口。允许提前登记尚无查询记录的域名，表单注明“精确匹配此域名，作用于整个实例”。需要覆盖子域名时，可前往「订阅与规则 → 本地规则」添加域名例外，并保留已有规则内容。

复用现有 `allow` 操作、版本校验和记录详情的放行权限。成功后原地显示活动条目及到期时间；失败时保留输入和错误原因。重复添加使用后端已有语义，临时条目可转为永久，已有永久条目不会因再次选择 10 分钟而缩短。

验收在关闭查询记录的隔离实例里，先为合成测试域设置覆盖子域的拦截规则，再手工放行其中一个从未查询过的域名。检查该域名得到放行判定、同级域名及其下级域名仍按原规则过滤；核对手工添加与记录详情添加显示在同一列表，移除或临时放行到期后恢复原规则判定。

### 白名单订阅

第二批在「广告过滤 → 放行列表」增加“添加白名单订阅”，预选“放行”类型。与「订阅与规则」共用订阅表单、预览和同一份来源记录；后者可按拦截或放行筛选。支持 HTTPS 地址、名称、刷新周期、立即刷新、停用和移除。类型随源保存并进入预览与编译；旧版本订阅及未传类型的旧客户端沿用拦截类型，保留其中已有的例外。手工精确放行继续单独管理。

**首版规则范围。** 白名单中的裸域名精确匹配，`||example.org^` 匹配该域及其子域；常用例外写法 `@@||example.org^` 同样可导入。界面预览列出匹配范围、规则数量和问题行。正则、客户端条件、重写等未实现语法沿用问题行与复核流程，带条件的规则禁止去掉条件后扩大放行范围。兼容基准见 [AdGuard DNS 规则语法](https://adguard-dns.io/kb/general/dns-filtering-syntax/)。

**命中行为。** 对已支持的域名规则，启用的白名单订阅命中时优先放行，再走当前 DNS 解析链。将订阅标识、名称、原始规则和活动版本传到 MosDNS 判定、域名检查与查询记录。手工放行和多个订阅可同时覆盖同一域名，移除一个来源时重算所有仍有效的规则。刷新失败沿用上一次生效版本。上游对放行和拦截引擎的检查顺序见 [AdGuard Home 实现](https://github.com/AdguardTeam/AdGuardHome/blob/v0.107.80/internal/filtering/filtering.go)。

**验收。** 使用同时含拦截域和放行子域的合成订阅，经 UDP 与 TCP 验证精确域、子域和相似域名的边界；核对命中来源，停用、重新启用及移除后再次实查。覆盖多个放行源重叠、刷新失败保留活动规则、旧订阅升级与重启后的结果。在兼容清单中列明已测试语法。

### 来源设备备注

针对 RouterOS 固定 DHCP 分配的内网设备，第二批增加实例级的手工备注。以 DNS 服务实际观测到的规范化 IPv4 或 IPv6 地址为键，一个地址可设置一个显示名称，例如“客厅电视”。相同名称可用于不同地址。路由器代转导致多个客户端共用同一来源地址时，备注只代表该可见地址。首版可独立使用，无需 RouterOS 账号或租约同步。

- **编辑入口**：管理员在查询或拦截记录详情的“设备来源”旁添加、修改或清除备注。点来源名称或 IP 仍按原地址筛选。编辑完成后保留时段、页码和展开记录。在“系统设置 → 来源设备”集中维护映射，支持按名称或 IP 搜索及预先录入固定地址。
- **显示规则**：首页来源 IP 排行、拦截来源排行、查询记录、拦截记录及详情统一展示“名称 · IP”，窄屏可分两行。无备注时显示原 IP，详情保留来源端口。排行聚合、筛选链接及原始事件继续使用 IP。历史列表展示该地址的当前备注，改名无须重写历史。
- **数据与权限**：增加实例级持久化映射和管理接口，复用现有鉴权和写操作保护。名称去除首尾空白并限制长度，地址使用标准库规范化。清除仅移除映射。页面批量读取映射并复用，避免每条记录单独请求；保存成功后更新同实例的显示，读取失败时仍可用原 IP 查记录。
- **验收**：在第 2 页给一个 IPv4 地址命名，当前记录、首页两类排行及过滤页都显示该名称，点击后按原 IP 下钻。改名、清除、重启后重新读取、相同名称对应两个 IP、等价 IPv6 写法、只读用户无法修改及跨实例隔离均有覆盖。确认清除备注后原始记录与统计计数一致。
