## 已完成的剩余代码

- 集成版拥有独立 package/lock，删除未使用的直接 js-yaml 依赖，更新兼容依赖并固定修复后的 minimatch；完整 `npm audit` **0 告警**。构建、Docker、CI 使用集成版清单，冻结独立版 39 文件保持不变。[依赖说明](../../frontend-dependencies.md)。
- 两个 Web worker 各四个线程，内核文件锁跨 worker 限制同时两个诊断请求；单查、对照、健康诊断及旧/v1 API 共用额度。容量满快速返回 503/UNAVAILABLE，附 Retry-After。
- manager 的预览/配置状态共用单个检查名额，零等待队列；维护锁最多等待约 50 ms，任务和能力读取保持独立。[容量说明](../../control-capacity.md)。
- 每次初始化/重启计算 cgroup 当前及祖先剩余内存，扣除维护预留，再应用 CACHE_BUDGET_MB 上限。内存不足时拒绝本次初始化，保留已有回退流程。不会持续调整运行中的缓存。
- 前端清单和原生包带源码摘要集合。Docker 增加可选 FRONTEND_IMAGE 构建参数；默认仍为 Node 22 Alpine，本次使用官方镜像公开镜像源的固定摘要构建，未修改主机 Docker 配置。

## 慢查询、CPU 和内存

同一主机、同一测试实例，四个诊断客户端循环请求，每次对照四个回环黑洞 DNS 目标。每个 DNS 请求会实际等待超时；另一路读取 instance/runtime/tasks。新版本持续 **180 秒**，含收尾实际约 183 秒。

该轮压力测量运行 `.opt2`；随后核对最终 `.opt3` 载荷，差异仅为后端版本常量、前端构建清单和源码摘要，功能代码保持一致。最终 `.opt3` 另完成原生 smoke、健康检查和下述真实 IPC 验证。

| 指标 | 旧版本基线 | 增加容量控制后 |
| --- | --- | --- |
| 状态/任务读取 P95 | 5.7925 秒 | **0.0239 秒** |
| 状态/任务读取最大延迟 | 5.8015 秒 | **0.234 秒** |
| 完成的状态读取 | 9 | **1542**，零失败 |
| 完成的慢诊断 | 28 | 117 |
| 明确返回忙的超额诊断 | 0 | **1741** |
| cgroup 内存峰值 | 185,528,320 bytes | **186,191,872 bytes** |
| 进程 RSS 之和峰值 | 292,327,424 bytes | 292,876,288 bytes |
| CPU 时间 / 实际时长 | 0.842 / 42.387 秒 | 27.115 / 183.070 秒 |
| CPU 占单核平均值 | 1.99% | 14.81% |

两轮使用相同客户端模型，但旧版本读取阻塞导致采样和总请求数量明显较少，新版本更快处理了大量轻量及忙响应。这些 CPU 数字不能作为相同吞吐下的性能对照，也不能声称 CPU 使用降低。RSS 之和会重复统计共享页面；cgroup 数字才是服务整体计费占用。测试是持续慢查询验收，未扩展为生产长时间 soak 或容量承诺。

真实独立 systemd cgroup 设置 512 MiB 上限，新增 **100 MiB** 占用后，计算出的缓存预算从 **379 MiB 降至 278 MiB**。临时测试 unit 已结束并回收。

最终安装版本另做真实 manager IPC 准入验证：持有维护锁时，**48 次预览/配置检查**均返回 UNAVAILABLE，最大约 **69 ms**；并发 **36 次任务读取**全部成功，最大约 **26 ms**。释放锁后配置检查恢复成功，未修改业务配置。

## 安装器及恢复

在标记实例对优化版本执行真实升级、原生 smoke、网页重启、强制 bootstrap 失败、manager 终止恢复；均通过。官方控制命令显式 rollback 恢复原版本、配置、身份和源文件摘要，再重新升级成功。另生成私有故障包强制初始化失败，安装器退出非零并自动恢复先前版本、数据及配置，随后健康检查通过。故障包只用于隔离验收，没有纳入候选交付。
