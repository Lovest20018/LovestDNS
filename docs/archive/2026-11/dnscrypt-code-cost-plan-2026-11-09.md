# DNSCrypt 源码成本拆分

从 `e9db8ae` 继续。41 的严格逐包初筛因发送空档停止，本阶段不追加同条件长测。只在新临时目录和独立网络命名空间分析源码成本，不替换在用服务、默认组件或操作 旧版正式机，不提 PR。

## 分离编译器与业务路径

固定已校验的源码和工具链归档：旧 2.1.5 / Go 1.22.5、旧 2.1.5 / Go 1.27.3、新 2.1.20 / Go 1.27.3。`packaging/dnscrypt-cost.lock.json` 记录摘要。

从上游原样提取 `plugin_cache.go`、缓存键、TTL 和深拷贝函数，保留各版本的实际 vendor。最小状态结构与报文 API 适配器只连接被测代码，不重写缓存算法；选定文件摘要全部记录。以 named-file 测试避免链接旧版 QUIC 的私有 TLS 符号，不为强行构建旧完整程序而改依赖。产物仅用于诊断，不能部署。

统一预制 A/AAAA 正应答，对查询解码、应答编解码、缓存键、深拷贝、缓存读命中和替换分别记录每次操作分配量、分配次数及进程 CPU 时间。固定次数运行、三轮轮换顺序，GOMAXPROCS=2，CPU 4–7，限时低优先级任务。编译与测量串行，每组从新进程开始；全部结果保留。

CPU 指标使用 Linux `getrusage(RUSAGE_SELF)` 的用户态/内核态总时间，单独记录 Go wall ns/op。进程 CPU 不把暂停期间的墙钟时间直接记作计算量，但频率、调度迁移、GC 和同机负载仍会影响结果，不能据此代替完整服务 P95/P99、RSS 或吞吐验收。

## 正确性先于优化

- 每种实现先确认 A/AAAA 编解码、克隆隔离、TTL、大小写/类型/类/DNSSEC 缓存键隔离和真实插件命中。
- 新版将 CheckingDisabled 纳入缓存键，深拷贝与响应问题核对也属于正确性处理；旧版的不同结果分别记录，不能为省 CPU 撤销新版校验。
- 定向检查 CPU 计数与 sleep 的区别，避免把墙钟命名为 CPU。成本微基准不生成网络查询，也不读生产缓存；普通制品功能验证只使用独立网络命名空间中的本地夹具，运行期间另做在用服务健康探测。
- 有明确热点才做窄补丁，并在新目录与原实现对照。每项优化须保持并发所有权、DNSSEC/EDNS、TTL 和缓存行为；小报文分配收益不直接扩大成整体加速。

本阶段交付成本证据与必要补丁，不将微基准通过标记为版本升级通过。UDP 接收队列补丁的权限/内核参数组合、完整制品性能、打包升级回退和持续观察仍是独立关卡。

## 初测后的定向补丁

前三组合各三轮完成后，确认新版缓存分片对 `[32]byte` 键走 `fmt.Sprintf` 回退路径。新增独立 `new-shard-fast` 诊断组合和显式 `cache` 普通制品候选：只为该精确类型使用现有随机种子的 maphash 直接哈希完整 32 字节。其他键类型、缓存键摘要、CD/DNSSEC、锁、深拷贝与淘汰算法保持原实现。

补丁先通过原版反例、全字节哈希/零分配、其他类型、容量/删除/清空及并发 race 检查，再用相同 Go、固定次数与原版交错三轮。缓存分片只在进程内存在，补丁随新进程加载；分片分布会变化，不能用于运行中已有缓存对象的热替换。此路径不读写 Redis/Unbound 历史缓存。

仅将 `cache` 加入可显式选择的候选；普通候选构建器的默认三组合、组件包入口和在用服务不变。评估收益只限被测路径，不外推整个分流/转发链路。
