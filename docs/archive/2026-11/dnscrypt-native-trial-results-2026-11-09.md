## 实际安装与 17 个检查点

新增 `scripts/test-dnscrypt-native-trial.py`，只接受全新 `dnstrial-*` 命名实例，在已隔离、只有 loopback 的网络中运行真实原生安装器。systemd drop-in 让服务、客户端和受控夹具处于同一 namespace；数据、状态、私有临时目录和备份均与在用实例分开。依赖预先检查齐全，安装仅使用包内 wheels，没有 apt 或系统库替换。

先安装 control，验证非分流模式，再启用分流模式。随后升级 combined、保存/重启、显式回退、拒绝损坏包，并制造一次实际 DNSCrypt 启动失败。**17 个检查点全部完成，434 次被计数 DNS 查询通过**；就绪探测、API 调用和夹具启动查询另计，不混入数字。

| 检查类别 | 查询数 | 实测结果 |
|---|---:|---|
| 新装非分流模式 | 2 | UDP/TCP 都返回受控本地记录 |
| 旧组合初始填充及候选新增缓存 | 72 | Redis 全 miss，两数据库各自到达预定本地上游 |
| 六个 RDB 复用检查点 | 264 | Redis 全 hit、零 miss、零上游请求 |
| control/combined 的直连与实际 SOCKS | 32 | UDP/TCP、HTTP/2、ALPN h2、来源路径和地址正确 |
| control/combined 经原生 MosDNS 分流 | 64 | 冷阶段分别到本地和 DoH；热阶段所有后端增量为零 |

每个完整缓存检查点包含 12 个名称各自的 A/AAAA，覆盖小写及混合大小写。相同名称的 A 在 DB 0/1 分别返回 `192.0.2.10`、`192.0.2.20`，检查数据库隔离；AAAA 同时核对受控 IPv6 答案。测试关闭预取和过期应答以确认本轮是新鲜缓存复用，TTL 保持正值并递减；它不代替过期应答专项。

六个复用检查点依次为 control 保存后整实例重启、combined 首次加载旧快照、combined 保存后重启复用旧条目、同次重启复用候选新增条目、显式回退后、启动失败自动恢复后。其中候选新增条目检查为 24 次，其余五项各 48 次，合计 264 次。所有检查都在进程内存缓存冷启动后执行，不能仅凭 RDB 文件加载成功判为命中。

每种包的两路 DNSCrypt 各发四个冷问题并用另一传输复查，实际 DoH 增量为 direct 4、proxy 4，HTTP/2 与 ALPN 计数一致，拒绝和 DNS 错误为零。原生分流每种包另查 16 个冷问题、16 个大写热问题；冷阶段八个本地问题、八次 DoH，热阶段本地、DoH、Redis 均无增量。夹具显式增加 `--route both` 供同一模板生成的两路进程共用，仍验证来源地址；默认 direct 策略未改变。

检查了管理/观测 API 的 native 身份、运行健康、两个 Unbound 层可用性及实例 ID 保留。用户配置、服务配置摘要和两个数据库标记在升级及回退后保留。候选的两份生成 TOML 也核实保留了 `pqdnscrypt=false`、`lb_strategy='p2'`，原用户模板未被覆盖。本轮没有连接网关 API 或验收网关观测开销。

## 两种恢复与备份

显式回退恢复 control、原服务配置和升级前数据；候选新增标记在恢复后的数据库中不存在。升级前原始 RDB 摘要保持不变。收尾用旧 Redis 在私有副本上读取两份被替换数据归档：显式回退归档仍有候选新增的 DB 0/1 标记和原标记；启动失败归档只有原标记。原快照均再次核对未变，没有通过删除候选数据完成回退。

损坏包使用正确的外层归档 SHA，但内部 DNSCrypt 包装器与 manifest 不符。真实升级入口在停止或切换服务前拒绝，原 PID 和当前链接不变。另一包有正确文件清单，只在 DNSCrypt 收到 `-config` 时故意返回 77；它能通过版本检查，并在切换后的 bootstrap 实际启动失败。安装器随后自动恢复旧版本、配置、数据和健康服务，48 次旧缓存查询再次全部命中 Redis。两次预期失败均保留日志，不计作未解释的组件故障。
