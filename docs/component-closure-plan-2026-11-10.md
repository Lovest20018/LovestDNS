# 组件升级收尾

日期：2026-11-10。基线 `3c7be9f`。按用户要求，先解决组件更新，再拓展功能；console4.1 的旧核心负载记录不计作新版组件验收。

## 固定范围

- 定制 MosDNS `240822.1` 继续冻结；用户规则、配置、实例身份和回退备份继续保留。
- DNSCrypt `2.1.20` 三补丁组合、Redis `7.2.17`、Unbound `1.26.2` 分别验证，再确定实际可交付组合。
- 使用现有测试环境。没有另一台稳定测试机时，保留调度和测量条件检查，报告所有失败，不反复重跑直到偶然通过。
- 本轮先在隔离实例工作，不升级正式实例，不推送或公开发布，不新增设备采集或界面功能。

## 实施顺序

1. **Unbound 缓存兼容**：实现只处理离线 RDB 副本的大小写键兼容工具。只增加可确认的目标键；保留所有原键和原始报文字节、时间戳、TTL、数据库及 Redis 绝对过期时刻。不覆盖现有小写键，不合并相互冲突的历史答案。未知结构、种子不符、CNAME 中间项、负应答和 DNSSEC 等范围分别报告并用真实旧新版查询验证，不将缓存报文直接当成最终答案。
2. **Redis 持久化与回退**：补齐旧 RDB 加载、新版写入及后台快照、新版重载、旧版读取新版快照和恢复原快照。验证 DB 0/1 隔离、类型、内容与过期语义；查询路径性能另行判断。
3. **DNSCrypt 与 Redis 性能**：固定实际普通制品、配置与输入，先校准原版重复性，再交错对照。逐项检查发送节奏、正确回答、内核时序、CPU、RSS 和尾延迟。兼容通过与性能通过分别记录；环境无法支撑的结论保持未验证。
4. **最终组合**：只有完成对应关卡的组件才进入组合，使用当前控制台源码重新构建并做隔离安装、升级、缓存和恢复检查。交付明确版本、来源、包摘要及已知限制。

本轮采用有界测试解决具体缺口，不设置固定等待 24 小时的控制台收尾门槛。发现实际组件错误时先修复与复验；性能受环境影响时明确证据缺口，不将其改写为无回归。

## 本轮性能协议

完成兼容测试后串行执行，CPU 4–7、配额 400%、内存上限 1 GiB，独立网络命名空间。先检查当前源文件、夹具、普通二进制摘要；DNSCrypt 去掉 NET_ADMIN，固定 `GOMAXPROCS=2`。沿用既有 CPU +5%、RSS +10%、P95/P99 增量 `max(基线×5%, 0.2ms)`，保留原始逐查询与内核配对。发生测量无效或基线重复性失败时，中止对应组件对照，不为通过而重复同条件测试。

- DNSCrypt：HTTP/2 直连、SOCKS，再 HTTP/1.1 直连、SOCKS，各做相邻原版 A/A，最多三对，每组 30 秒、100 QPS、q64。相邻两组的 P95/P99 差值均须不超过上述门槛；任一组逐包节奏、答案、路由、协议或资源检查失败即停止该组件。全部校准通过后，原版／同工具链 upstream／combined 做每组 30 秒、三轮交错初筛；只有初筛通过，才做 120 秒、五轮同矩阵正式对照。不得把新旧编译器差异的比较归因于单个补丁。
- Redis：缓存命中入口、串行夹具、500 QPS、q64，原版每组 30 秒，最多三对相邻 A/A，每组独立填充唯一问题并重启 Unbound。答案、全量内核配对、每条 Redis 命中、零上游和资源条件有效后，检查相邻 P95/P99。30 秒阶段仅用于校准；通过后才启动原版／仅新 Redis 每组 120 秒、五轮交错正式对照。原正式时长和阈值不因校准较短而下调。

DNSCrypt 和 Redis 分别判定，前者条件失败不阻止后者校准。若未能建立有效对照，交付已完成的兼容修复和证据，继续保留默认升级限制，不能据此合成“升级完成”的整包。

## 实际大快照补充

受控持久化通过后，复用此前完成且摘要固定的实际历史大快照，只读取得副本，转移到测试环境验证。与性能阶段错开，限制 CPU、内存和时间，不向正式 Redis 发送命令或在正式机启动试验。测试机保留原文件、在新目录用禁用 TCP／AOF／自动保存的独立 Redis 加载；验证全量键／值／DB／截止时刻摘要、新版 BGSAVE、新版重载、旧版读取及原快照恢复。写快照前预留文件大小和至少 1 GiB 余量；只读阶段使用新目录中的硬链接避免重复大文件，写阶段在加载后移除新建链接再生成新文件，原快照始终保留并核对摘要。此项不等同于实际全量 DNS 答案回放。

随后在同一份不可变输入上运行实际交付的离线计划和准备入口，分别用新旧 Redis 加载输出。按每个计划别名的原字节和绝对截止时刻派生预期增量，再与完整快照摘要比较，要求输出恰好等于全部原数据加计划别名。容量记录限定为该隔离配置下的文件、内存和零淘汰结果，正式配置下的容量压力仍需单独验证。仅在摘要和完成状态确认后释放本轮新建的临时大文件；保留原快照、报告和失败记录。
