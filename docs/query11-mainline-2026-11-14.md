## 采集时钟修复

六小时主动测试按每秒一次发送 21,600 次查询，DNS 响应全部符合预期；采集记录为 21,598 条，缺两条，因此完整性检查判为失败。服务和组件身份持续不变，没有自动重启。合成回环来源不代表真实终端接入。

确定性复现发现，旧采集循环在检查入口前读取单调时钟、检查后读取系统时钟；入口检查变慢会使偏移比较看起来发生跳变，触发关联重置。query1.1 改为相邻读取两种时钟。新增六个回归用例覆盖 IPv4/IPv6、150 ms 慢检查，以及真实的正负 200 ms 时钟跳变；查询记录测试共 27 项通过。

修复后五分钟测试发送 300 次查询，响应及对应采集记录均为 300/300，逐条字段匹配；新增误重置、待匹配丢弃、内核／队列／存储丢弃和捕获错误均为零。六次健康观测通过，原历史、配置与账户保留。没有据此声称修复后已通过六小时或长期测试。

部署准备中的诊断脚本转换错误和测试空间预算不足曾各触发一次恢复，均保留失败及恢复证据；最终使用同一份已验证修复包完成短测。试用实例地址、账户、进程标识、原始记录和恢复路径不进入公开材料。

## 六项交互与 UI 修复

| 问题 | 当前行为 |
| --- | --- |
| 样本查询被历史列表挡住 | 查询记录、主动查询、链路对照分区；首页直接进入查询，记录行可带入域名与类型 |
| 暂停采集与页面刷新混淆 | 统一为暂停／恢复自动刷新；后台记录有独立开关，各页均可恢复刷新 |
| HTTP 环境复制静默失败 | 统一捕获不可用与拒绝，提供成功提示、全选文本和下载回退 |
| 跨页丢失筛选 | 条件、页签、游标与刷新选择进入 URL；按实例记住会话上下文，清除筛选和过期游标均有处理 |
| 手机表格难以核对响应 | 小屏使用卡片，直接显示来源、域名、响应及耗时，入口信息可展开 |
| 深色说明链接偏暗 | 明暗主题使用独立链接与悬停色，保留可见键盘焦点 |

本地合成环境覆盖 131 条记录、1360×900 桌面及 390×844、320×844 窄屏。实际走查跨页／刷新／共享链接恢复、分页、主动查询、两条链路对照、异常响应保留旧结果和明暗主题。长域名及 IPv6 可换行，主要卡片字段无需横向拖动。

复制在 localhost 成功；另一非安全 HTTP 来源实际进入手动复制回退，全选及下载内容一致；权限拒绝另有单元用例。说明链接实测明亮对比度约 5.72:1、深色约 9.19:1，键盘焦点可见。旧 headless Chrome 脚本的一次运行在 `Runtime.evaluate` 超时，未计为通过，交互验证由应用内浏览器完成。

UI 修复后的 TypeScript、Vite、ESLint、52 项前端测试及 39 文件独立版冻结检查通过。API 契约重新调用真实 Flask 处理函数导出 32 组确定性合成样例；相对 query1 的业务响应结构不变，版本与源码摘要更新为本轮版本。

本地构建与截图、原始查询及恢复证据保留在忽略目录中。前端界面验证不代替 Linux 原生安装验证，五分钟采集检查不代替真实设备接入或长期运行验收。
