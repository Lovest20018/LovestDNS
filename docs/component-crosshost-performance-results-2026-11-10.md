# 另一宿主机上的组件性能对照结果

日期：2026-11-10，从 `95a55fb` 继续，执行[固定方案](component-crosshost-performance-plan-2026-11-10.md)。**Redis 7.2.17 通过本机受控缓存命中路径的五轮性能筛选；DNSCrypt 旧版校准的第三对 P99 重复性失败，未开始候选对照。** 本轮已结束，正式实例未升级。

用户批准换到现有 Debian 12 / KVM 宿主机，用隔离实例先校准旧版，再有条件比较候选。前轮调度失败和指定复测结果继续保留，不因换机器而追改其验收结论。

## 环境与固定输入

实际宿主机四核、内核 `6.1.0-43-amd64`。试验使用 CPU 2–3、150% 配额、1 GiB 内存上限、Nice 10 和独立 loopback 网络命名空间；独立心跳及生产健康探测使用另一 CPU 组。旧版为 Redis 7.2.5、Unbound 1.21.1、DNSCrypt 2.1.5。普通候选、源码锁及夹具沿用此前通过摘要核对的制品，没有为本轮重新编译。

使用未增加发送跟踪的冻结方法，输入归档 SHA-256 为 `12193bd2aad2fb8b395024e44cf38b090ea7988564e0c1378076668326d60d70`；96 个源码输入逐项核对。DNSCrypt 的普通 paced-udp 和 DoH 二进制与前轮相同。Redis 使用该宿主机此前已验证的自带加载器 dnsperf 包装器，实际程序及全部依赖一并记录摘要；其中实际 dnsperf 二进制也与前轮一致，SHA-256 为 `098aca9779e20370f45f61d40d851e59030f8e8c504f421a303c9d61616b5b47`。新旧版本仅在本机同条件比较，跨机器绝对数值不用于推断某一虚拟化平台或版本的因果影响。

生产核心、配置、规则、身份、账户、host resolver、内核参数和原备份在试验前记录，只对新的私有副本与合成数据执行试验。准备阶段第一次解包检查将六个文件误写成七个，在解包及发送查询前中止；修正该计数后继续，原失败记录保留，没有重做已完成的性能测量。

## Redis 旧版校准

500 QPS、q64、串行夹具；每组测量 30 秒，独立准备唯一问题，并只重启 Unbound 后检查 Redis 命中。

| 相邻对 | P95（ms） | P99（ms） | P99 差值（ms） | 结果 |
| --- | --- | --- | ---: | --- |
| 1 | 1.141 / 1.112 | 2.034 / 2.120 | 0.086 | 通过 |
| 2 | 1.192 / 1.156 | 2.039 / 2.056 | 0.017 | 通过 |
| 3 | 1.098 / 1.061 | 2.072 / 2.043 | 0.029 | 通过 |

三对的 P95 / P99 均满足固定重复性门槛 `max(两者较小值×5%, 0.2ms)`。六组共 90,000 条正式查询全部正确、零丢失，每条均命中 Redis，未命中及上游访问为零；另有 90,060 条准备查询。准备与测量的完整内核配对、CPU 限流和内存事件检查均有效。

## Redis 五轮正式对照

旧版／仅新 Redis，每组 120 秒，五轮交错，共十组。**本机受控 cachedb 命中路径的性能筛选通过**；全部测量与资源条件有效。

| 五轮中位数 | 旧版 7.2.5 | 新版 7.2.17 |
| --- | ---: | ---: |
| P95（ms） | 1.148 | 1.187 |
| P99（ms） | 2.254 | 2.181 |
| CPU 秒／百万查询 | 178.333 | 180.333 |
| 峰值 RSS（MiB） | 43.36 | 42.57 |

CPU 指标为 Redis 与旧版 Unbound 进程之和，新版增加约 1.12%；RSS、吞吐及 P95/P99 均符合原门槛。十组共 **599,998 条正式查询**全部正确、零丢失，Redis 每条命中，未命中和上游访问为零；另有 **600,100 条准备查询**，准备与正式测量的内核配对均完整。阶段 cgroup 没有新增 CPU 配额限流、memory max 或 OOM 事件。

该结论限定于 500 QPS、合成唯一问题、受控串行夹具及当前 CPU／内存条件的命中路径，不能推广为生产分流、冷查询、最大吞吐、AOF 或任意缓存规模的一般性能结论。Unbound 本轮保持 1.21.1；旧数据兼容与持久化另见[组件收尾记录](component-closure-results-2026-11-10.md)。正式服务与默认组件没有升级。

## DNSCrypt 旧版校准

100 QPS、q64、每组 30 秒，去掉 NET_ADMIN、GOMAXPROCS=2，使用严格发送节奏及实际 TLS HTTP/2 直连路径。六组均为旧版 2.1.5：

| 相邻对 | P95（ms） | P99（ms） | P99 差值（ms） | 重复性 |
| --- | --- | --- | ---: | --- |
| 1 | 1.583412 / 1.514209 | 2.756008 / 2.779964 | 0.023956 | 通过 |
| 2 | 1.587171 / 1.622094 | 2.788600 / 2.619697 | 0.168903 | 通过 |
| 3 | 1.537826 / 1.524129 | 2.736964 / 2.483545 | **0.253419** | **未通过** |

六组共 **18,000 条查询**全部正确、零丢失；TLS、HTTP/2／ALPN、直连路由、内核配对、发送程序、逐包节奏及资源检查均有效，Redis 分支结束后也没有新增限流或内存异常。三对 P95 均满足 0.2 ms 门槛，但第三对 P99 差值超过 0.2 ms；因此是**有效测量下的原版尾延迟重复性不足**，不是候选版本的失败，也不是发送节奏无效。

按方案在首次失败后停止该组件，没有重跑。SOCKS、HTTP/1.1、候选初筛和正式 DNSCrypt 性能矩阵均未启动，不能签署 combined 通过或回归。两组件分别判定，DNSCrypt 校准失败不撤销 Redis 已完成的独立通过结果。

## 调度与因果边界

本轮 DNSCrypt 内核查询间距均在 **5.785–13.974 ms**，满足 5–50 ms 固定范围；没有出现前轮约 275 ms 的发包空档。独立心跳在整个约 50 分钟窗口记录 293,084 个样本，最大间隔 **39.618 ms**。所有样本与原始逐查询记录保留，未据心跳删除查询、修改分位数或放宽门槛。

这说明该有限窗口内发送节奏有效，尚不能证明前轮停顿由 Workstation、重启或某个组件引起。不同宿主机、CPU／配额、背景生产负载等条件同时变化；不能用跨机器数值归因于单一因素。本机的 DNSCrypt 旧版仍未通过全部重复性校准，性能缺口继续保留。
