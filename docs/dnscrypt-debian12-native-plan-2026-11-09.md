# DNSCrypt Debian 12 原生整包隔离验收方案

从 `cea0748` 继续。用户已授权在旧版 Debian 12 正式机做隔离测试，本轮继续该授权范围：只为全新 `dnstrial-*` 命名实例安装测试包，在用 `lovestdns` 服务不参与升级、停止、故障注入或数据导入。

1. 只读核对 Debian 12、Python 3.11、systemd 252、内核及依赖，依赖必须齐全，不允许触发 apt 操作。核对在用服务 PID、重启数、发布目录、核心与依赖摘要、配置摘要、host resolver 和 rmem 参数；持续探测真实 DNS 及资源余量。
2. 在测试机从同一个已校验旧原生归档生成匹配 control/combined，二者共同刷新当前应用及安装器，只对 combined 替换普通 DNSCrypt 候选。保留旧前端、wheels、模板及其他核心，逐文件校验后传输。组件保持候选标记，不修改默认锁或 PR。
3. 在 Debian 12 创建仅 loopback 的网络命名空间、新数据和状态目录及新 systemd 单元。测试程序与新服务使用同一 namespace，CPU 2–3，服务 CPU 配额 125%、768 MiB 内存、低调度权重；测试控制程序另限 50% CPU、512 MiB 内存和总运行时限。不得挂载生产数据。
4. 复用既有 17 检查点整包工具，验证新装递归、分流、两个 Redis 数据库的 A/AAAA 与混合大小写、重启后首次缓存命中及零回源、升级后旧 RDB 复用、新写入持久化、直连/实际 SOCKS、HTTP/2/ALPN、UDP/TCP、显式回退、坏摘要拒绝、真实 DNSCrypt 启动失败自动恢复。保留原日志，遇到异常先停止并诊断。
5. 完成后停止并禁用新实例，删除临时 namespace，检查无残留组件；保留合成测试备份并只读核验其内容。再次核对在用服务、配置、组件、resolver 与 sysctl。归档输入、包、方法、资源及结果摘要，公共报告不包含现场地址或凭据。

主机可用内存低于 1 GiB、磁盘低于 2 GiB、在用服务身份变化或连续两次 DNS 健康失败时终止。该轮最多执行一次完整矩阵，准备或工具失败另列，不追改原失败。

本轮是 Debian 12 实际宿主机的原生 systemd 整包功能验收，不是生产实例升级、实际旧缓存全集验收、稳定性能对照、两小时负载或 24 小时观察；性能关卡保留原门槛。
