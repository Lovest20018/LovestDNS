## 采集依据

冻结 MosDNS `kkkgo/mosdns:240822.1`，二进制 SHA-256 为 `33b3ef9740a071b4f4909ab5c26d8d29ae3401415578bdaad897267d04e09fb0`。独立实例的 UDP/TCP 实测确认 `query_summary` 能输出客户端 IP、域名、类型、RCODE、请求编号和核心处理耗时；没有返回地址，传输类型需要额外入口标记。

本轮使用独立被动采集进程，不改 MosDNS 二进制、日志级别、配置流水线或 DNS 监听。Linux 接收用 packet socket 在内核过滤已确认入口端口，只解析当前服务网络命名空间的本地地址。入口由 observer 的进程监听证据提供，并再次核对当前 PID、启动时间和实际持有的 socket。采集故障、存储错误、Web 重启均不参与 DNS 转发。

实现依据：[MosDNS 请求摘要](https://github.com/kkkgo/mosdns/blob/main/plugin/executable/query_summary/query_summary.go)、[请求上下文](https://github.com/kkkgo/mosdns/blob/main/pkg/query_context/context.go)、[Linux packet socket](https://man7.org/linux/man-pages/man7/packet.7.html)、[Linux socket filter](https://docs.kernel.org/networking/filter.html)。上游源码用于解释机制，具体冻结二进制能力以实测为准。

## 默认与容量

- 默认关闭；管理员在“DNS 诊断 → 最近查询”明确开启，无需重启 DNS。开关持久保存，关闭保留已有记录。
- 最多保留 24 小时、100,000 条。数据库页上限 31 MiB，另预留回滚日志及元数据，使查询存储预算保持在 64 MiB 内。时间清理每 5 秒执行，读取立即排除过期事件；容量达到上限时淘汰最旧记录。
- 待保存事件队列 512 条，待响应事务 2,048 条，TCP 方向流 128 条；每方向最多一帧 65,535 字节 DNS 数据。写入按最多 128 条、最长 20 ms 合批，避免逐条同步提交。
- 超额丢弃、内核丢包、TCP 缺口、未解析报文和存储错误均计数。关联重置、启停或清空丢弃单独记录。计数属于本次采集进程，重启后更换会话编号，不宣称连续全量历史。
- 数据位于私有状态目录 `queries/events.sqlite`；设置位于 `query-recording.json`。Unix socket 权限 0600，目录 0700。原生实例备份状态目录时也会包含查询域名和来源 IP。

## 字段与语义

事件包括采集会话/事务编号、入口时间、来源 IP/端口、入口地址/端口、组件、域名、QTYPE/QCLASS、UDP/TCP、RCODE、Answer 数量、最多四个 A/AAAA 地址及完整性标志。列表响应绑定持久实例 ID。

耗时使用入口请求和响应的内核报文时间戳间隔，标记为 `passive_entry_packet_interval`，包含核心处理及本地调度，不是上游延时或客户端端到端延时。明显时钟跳变会清空关联。十秒内未配对的请求标记为“未观察到响应”，耗时和 RCODE 留空，不推断 DNS 超时。

相同传输、源/目标地址及端口、DNS ID、域名、类型、类的重复在等待响应期间合并并显示 `same_key_packets`；间隔从首次观察的报文起算。UDP 截断及随后的 TCP 事务分别记录，不推测两者是否属于同一个应用请求。TCP 需要看到握手；序列缺口后停止解析该方向，等待新握手，十秒空闲后释放跟踪。

来源 IP 是实例入口实际看到的地址，NAT 后可能只见路由器。本机入口流量可能含面板诊断，内部上游端口不作为客户端入口。IP 不能换算为物理设备数量。设备备注、IP 聚合、规则命中、实际分流路径和缓存命中均未实现；后两项事件字段始终为空。

不支持加密 DNS 解密、IP 分片、IPv6 扩展头、启用前已建立的 TCP 流，以及超过八个入口端口的配置。报文过滤位于协议栈入口附近，DNAT/透明接管可能导致缺失；没有据此声称终端接入或转发路径已验证。没有保存原始报文、TXT 内容或任意完整响应。

## API 与部署

仅管理员会话/管理 Token 可访问；外部只读 Token 没有查询历史权限。管理 Token 仍受外部 API 开关约束；浏览器写入仍要求 CSRF。

| 路径 | 方法 | 用途 |
| --- | --- | --- |
| `/api/v1/query-recording` | GET | 状态、容量、计数、当前入口 |
| `/api/v1/query-recording` | PUT | `{ "enabled": true/false }` |
| `/api/v1/query-records` | GET | 最近查询，默认 50、最多 100 条 |
| `/api/v1/query-records` | DELETE | 清空记录并使旧队列/关联失效，保留开关 |

筛选：`source` 为完整 IP，`domain` 为大小写不敏感的字面包含匹配，`qtype` 为数值类型；`before` 使用上页 `next_before` 游标。缺失采集服务返回 503，不补造零值或记录。响应禁止缓存。

原生包会新增独立 supervisor 程序 `query-recorder`，并在 systemd 的地址族白名单加入 `AF_PACKET`。升级必须走安装器更新服务单元，单独覆盖应用文件不足以启用采集。Linux 进程需具备 `CAP_NET_RAW`；受限容器缺少权限时显示不可用，不要求为此开启 privileged。采集日志可在服务信息中选择 `query-recorder`。
