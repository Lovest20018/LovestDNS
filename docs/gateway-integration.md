# 可选 LovestGateway 联动

在 LovestDNS 的“设置 → 网关联动”填写网关观测 API 固定地址和只读 Token，先测试，再“保存并启用”。默认关闭；不开启仍可独立使用 DNS。

地址格式为 `http://192.0.2.10:18788/api/v1`。支持固定 IPv4/IPv6；HTTP 仅允许内网/回环，公网使用 HTTPS 并校验证书。网关侧需要已经开启观测 API；此页面不会修改网关设置或转发策略。

Token 只写入 DNS 实例私有状态目录，页面不回显。留空可沿用同一目标的已存凭据；切换目标必须重新提供。保存使用版本检查，“断开并清除凭据”会停止联动并删除保存的 Token。现有实例状态备份包含此私有配置。

保存并启用后，侧栏显示独立入口“网关观测”，运行概览也提供快捷入口。进入观测页时读取一次状态与首批记录，之后按需刷新；不会后台轮询网关。网关不可用时保留入口并显示错误，主动断开后隐藏入口。原 `#/diagnostics?tab=gateway` 深链继续打开观测页。

连接记录以表格呈现客户端 IP、域名/目标、处理方式、状态和时间，详细证据按行展开；窄屏可在表格区域横向滚动。支持：

- 实例身份、版本、模式、能力与原始采样时间。
- 近期 TCP 连接和持久观测历史，支持域名/来源 IP 精确筛选和分页。
- Mihomo 当前快照的规则与连接链，在前 100 条快照内筛选。
- 域名或 IP 对应的当前 FakeIP 映射（在页内展开查询）。

只展示当前网关声明支持的功能。`mode_dispatch` 是实际模式派发，不是域名规则命中；Mihomo 是独立快照。记录可能有缺口，未观察到不等于没有流量；当前 FakeIP 映射不证明历史归属。网关记录和 DNS 诊断分别展示，不自动认定属于同一次访问。

无配置不访问网关。读取失败保留带时间的上次结果，游标失效需重新读取。设置页仅负责连接配置和测试。新接口为浏览器管理员会话专属，写操作要求 CSRF；DNS 对外管理/只读 Token 不能调用这些接口。没有主动出站探测或跨产品配置写入。

未包含兼容修正的网关观测 API 在 Mihomo 空闲时可能因核心返回 `connections: null` 而报 HTTP 502 `INVALID_CORE_RESPONSE`。网关侧应仅将这个空值规范为列表，其他异常结构仍报错；前端不能把读取错误当成无连接。测试实例当前为 Gateway 0.2.3，已补入该修正并通过近期连接、持久历史、Mihomo 快照及 FakeIP 的真实 HTTP 和浏览器复验。当前为网关测试实例的兼容补丁，重新安装未包含修正的网关包可能覆盖它。
